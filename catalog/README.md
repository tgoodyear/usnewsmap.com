# Catalog

The reference data that places a newspaper title on the map: a US gazetteer built from Census data, and hand-written corrections to it. Status: live. `usnm-ingest` compiles these files in, so a change ships with the next ingest image and applies on the next ingest run in every environment ([design 04 §4.6](../docs/design/04-data-sources-and-ingestion.md), 08 §8.9: hand-curated state lives in git).

| Path                           | What it holds                                                                                                                                                           | Edited by                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `gazetteer/us-places.csv`      | Every incorporated place and census designated place in the US with its internal point: `state,name,lat,lon`, a header and about 32,000 rows, sorted by state and name. | generated by `scripts/data/build-gazetteer.py` |
| `overrides/places.json`        | Corrected coordinates, precision or name for a place                                                                                                                    | by hand                                        |
| `overrides/place-aliases.json` | Misspelled and renamed towns, so their titles share a place with the town's other titles                                                                                | by hand                                        |
| `overrides/title-places.json`  | The city of a title whose LoC record lists several places                                                                                                               | by hand                                        |
| `overrides/titles.json`        | A title whose pages ship under an LCCN with no record on loc.gov, mapped to the LCCN of another LoC record for the same title                                           | by hand                                        |
| `overrides/README.md`          | The audit trail every override entry carries and the format of each file                                                                                                |                                                |

## What reads it

- `usnm-ingest` embeds all five data files with `include_str!` (`crates/usnm-ingest/src/places.rs` for the gazetteer, aliases and title places; `titles.rs` for the place and title overrides). The `geocode` and `titles-sync` subcommands use them. `crates/usnm-ingest/src/audit.rs` checks the audit fields.
- `docker/Dockerfile.ingest` copies this directory into the build (`COPY catalog ./catalog`).
- `scripts/ci/changes.sh` counts a change under `catalog/` as a Rust change, so the Rust job runs. `cargo test -p usnm-ingest` parses each override file into a struct that rejects unknown fields, checks the audit fields and requires the sorted order ([development guide](../docs/development.md#json-data-files)).

## Changing it

- **An override.** Add the entry to the right file in `overrides/`, keeping the sort order and alphabetical keys, with the fields `added`, `reason`, `source` and `ref`. [`overrides/README.md`](overrides/README.md) has the format of each file. [Operations](../docs/operations/catalog-and-releases.md#the-title-catalog) says when to use which file and how to check the effect with `cargo run -p usnm-ingest --example place-report`.
- **The gazetteer.** Do not edit the CSV by hand. To refresh it for a newer Census year:

  ```sh
  scripts/data/build-gazetteer.py --year 2025            # downloads that year's national places file
  scripts/data/build-gazetteer.py --zip 2025_Gaz_place_national.zip   # or use a local copy
  ```

  The script writes `gazetteer/us-places.csv` and nothing else changes. The Census file is a work of the US government and in the public domain.

A change that moves an already published title to another place waits for the next full release. [Operations](../docs/operations/catalog-and-releases.md#the-title-catalog) explains why.
