# Configuration

The API (`usnm-api`) reads its settings from environment variables (`crates/usnm-api/src/config.rs`). The defaults suit local development against the synthetic fixtures. In Azure, Bicep sets them (`infra/modules/containerapp.bicep`). On-prem serving writes the same values into its `api.env` with `scripts/onprem/serving/gen-env.sh`, whose `--check-app` compares the result with the Azure app and lists the intended differences.

An empty value counts as unset. Flags take `true` or `false`; the API refuses to start on a value it can't parse or one out of range.

## Searches and limits

| Variable                     | Default | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `USNM_SEARCH_TIMEOUT_SECS`   | `10`    | How long a visitor's request waits for a response (plus 2 s with a persistent cache); past it the API answers `202 Accepted` and the search carries on (06 §6.3.5)                                                                                                                                                                                                                                                                                         |
| `USNM_COMPUTE_CAP_SECS`      | `120`   | Limit on one search computation and each backend call in it, from when it gets its slot. Past it the search fails with a `503` timeout, which is not cached. A search still queued for a slot after this long gets `503 /errors/busy`                                                                                                                                                                                                                      |
| `USNM_COMPUTE_CONCURRENCY`   | `2`     | Searches this process computes at once, including those still running after a `202`; when all slots are busy a new search queues (06 §6.6). In Azure the deployment setting of the same name is a budget: with a shared searcher (the searcher app, or index-storage serving) provision divides it by `USNM_API_MAX_REPLICAS`, rounding down, and refuses a budget smaller than the replica count (#364); with a sidecar each replica gets the full budget |
| `USNM_SEARCH_QUEUE`          | `16`    | Searches allowed to wait for a slot, first come, first served. Each keeps its place while its visitor keeps asking, and its `202` says how many are ahead. A search that finds the queue full gets `503 /errors/busy` at once                                                                                                                                                                                                                              |
| `USNM_ABANDON_AFTER_SECS`    | `15`    | A computation no request has waited on for this long is cancelled (the visitor changed the search or left). At least 5                                                                                                                                                                                                                                                                                                                                     |
| `USNM_BACKEND_CONCURRENCY`   | `8`     | Backend queries allowed at once; waiting for one counts against the computation limit                                                                                                                                                                                                                                                                                                                                                                      |
| `USNM_SEARCHER_METRICS_SECS` | `60`    | With the Quickwit backend, how often the API reads the searcher's cache, thread pool and runtime metrics from `USNM_QUICKWIT_URL/metrics` and reports them as `api.searcher_cache_*`, `api.searcher_pool_tasks` and `api.searcher_runtime_*` (08 §8.1.2). `0` turns this off, and with it the API's only way to see that the searcher restarted, so a restarted searcher is no longer warmed (06 §6.5)                                                     |

## Warm-up and readiness

| Variable                                | Default                                         | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `USNM_PREWARM_QUERY_SECS`               | `60`                                            | Cache warm-up: limit on each query                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `USNM_PREWARM_BUDGET_SECS`              | `900`                                           | Warm-up before a publish swaps a new version in: limit on the whole run; the rest is skipped. At most 86400                                                                                                                                                                                                                                                                                                                                                                         |
| `USNM_PREWARM_STARTUP_BUDGET_SECS`      | `300`                                           | The same limit for the warm-up after a start. By default the replica isn't ready until it ends, so in a rollout the old revision serves meanwhile. At most 86400                                                                                                                                                                                                                                                                                                                    |
| `USNM_PREWARM_TOP_SEARCHES`             | `20`                                            | Warm-up: after the examples, this many of the most frequent searches in the search log, the examples searched most going first (`0` turns both off)                                                                                                                                                                                                                                                                                                                                 |
| `USNM_PREWARM_LOG_DAYS`                 | `28`                                            | Warm-up: how many days of the search log are counted, back from the day before                                                                                                                                                                                                                                                                                                                                                                                                      |
| `USNM_PREVIEW_WARM_INTERVAL_SECS`       | `10`                                            | The example-preview warm-up's pause after each step that rendered a map image, so visitors' share images aren't kept waiting. 1 to 3600                                                                                                                                                                                                                                                                                                                                             |
| `USNM_READY_CAP_SECS`                   | `USNM_PREWARM_STARTUP_BUDGET_SECS` + 60 (`360`) | After a start, `/readyz` reports ready once the warm-up ends or this much time passes; past it the replica serves while the warm-up finishes. The default lets a rollout move traffic only to a warm replica (06 §6.6). At most 86400. `infra/modules/containerapp.bicep` sets both from one budget so the startup probe covers the cap; where the app scales to zero it sets a startup budget of `0` and a cap of `60`, because the visitor who woke the replica is waiting for it |
| `USNM_READY_REQUIRES_PUBLISHED_INDEXES` | `false`                                         | `true`: `/readyz` also fails while the published version (`current.json`) names an index the search engine lacks (a 404 from Quickwit's metastore, or no file in the memory backend's `indexes/`), as the last reload found. The replica keeps serving the version it has either way. Leave it off where a failing readiness probe takes the replica out of traffic (Container Apps), which would turn serving the previous version into an outage                                  |

## Clients

| Variable                      | Default                 | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `USNM_ALLOWED_ORIGINS`        | `https://usnewsmap.com` | Comma-separated CORS origins (GET only). `/mcp` also allows `https://usnewsmap.com` and `https://api.usnewsmap.com`                                                                                                                                                                                                                                                                                                              |
| `USNM_RATE_PER_MIN`           | `120`                   | Per-client token bucket refill rate on `/v1` and `/mcp` (`0` turns rate limiting off)                                                                                                                                                                                                                                                                                                                                            |
| `USNM_RATE_BURST`             | `40`                    | Per-client bucket size; at least 1                                                                                                                                                                                                                                                                                                                                                                                               |
| `USNM_TRUSTED_PROXY_HOPS`     | `1`                     | Proxies that append to `X-Forwarded-For` (1 = Container Apps ingress, 2 = a proxy such as Front Door plus ingress, 0 = use the peer address)                                                                                                                                                                                                                                                                                     |
| `USNM_TRUST_CF_CONNECTING_IP` | `false`                 | `true`: the client address (for the rate limit and page views' location) comes from Cloudflare's `CF-Connecting-IP` instead of `X-Forwarded-For`, and only on requests whose peer is loopback, as behind cloudflared and a proxy on the same host. Any other request counts its peer's address, and `USNM_TRUSTED_PROXY_HOPS` is ignored. On-prem serving turns it on; it stays off on Container Apps, whose ingress is the peer |

## Search features

| Variable                       | Default   | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------ | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `USNM_AMERICAN_STORIES_SEARCH` | `true`    | `false` searches LoC's text alone on a version built with American Stories' text, as if `current.json` had no `american_stories`: no `text_as` fields, no `matched_in` or `snippet_source`, no `total.american_stories_only`, and `/v1/meta` says `"american_stories": false` (05 §5.5.4). Responses computed with it off are cached under their own keys (`…\|american_stories=off`); with it on the keys are unchanged, and Japanese queries keep theirs either way. It has no effect on a version that searches its texts in one field (`text_layout` 2 or 3, 05 §5.5.7): the API logs a warning and searches both. Production sets it from the deployment setting of the same name ([operations](../operations/american-stories.md#american-stories-text)) |
| `USNM_CONGRESS_SEARCH`         | `true`    | `false` turns Congress search off on a version that has a Congress index set (#229): the Congress indexes aren't loaded, `source=congress` answers 422 before any cache is read, and `/v1/meta` says `"congress": null`, with no rebuild or change to `current.json`. With it on, a Congress set that fails to load is dropped with a warning and the newspapers still serve (06 §6.3.10). Production sets it from the deployment setting of the same name; browsers may keep a Congress response for up to a day (06 §6.5)                                                                                                                                                                                                                                    |
| `USNM_PAGE_LANGUAGE_FILTER`    | `smaller` | On a version with page languages (05 §5.5.8), how `lang=` is rendered: `smaller`, the side with fewer pages (`page_language:IN [L]`, or the complement `NOT page_language_set:IN [...]`), or `match`, the match side always. Both find the same pages, so cached responses serve either way; the setting is for measuring one against the other (#289). Production sets it from the deployment setting of the same name (Bicep `pageLanguageFilter`; empty leaves it unset)                                                                                                                                                                                                                                                                                    |
| `USNM_BROWSE_PAGES`            | `false`   | `true` lets `/v1/hits` list one newspaper's pages without a search word (#274, 06 §6.3.4): exactly one `lccn` and no `q`, by date, each page with the opening of its text as its snippet. `/v1/meta` reports it as `browse_pages`, and the site offers "Browse pages" in the newspaper filter only then. A list with no word has no posting list to skip splits by, so it reads every split of the version for the title's pages. Production sets it from the deployment setting of the same name (Bicep `browsePages`; only `true` sets it); prod has it on                                                                                                                                                                                                   |

## Credentials

The Blob and Cosmos clients (`crates/usnm-store/src/credential.rs`) pick a credential from the environment:

| Variable                                                  | Meaning                                                                                              |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `IDENTITY_ENDPOINT`, `IDENTITY_HEADER`, `AZURE_CLIENT_ID` | Set by Container Apps: the managed identity. `AZURE_CLIENT_ID` selects the user-assigned identity    |
| `IDENTITY_ENDPOINT`, `IMDS_ENDPOINT`                      | Set by the Azure Arc agent on an on-prem host, with no `IDENTITY_HEADER`: the machine's Arc identity |
| `USNM_TOKEN_CACHE`                                        | A private directory where processes using a managed or Arc identity share their tokens               |

With neither identity, the clients use the Azure CLI login (`az login`).

## Tests only

`USNM_FIXTURE_SLOW_TERM` (unset) and `USNM_FIXTURE_SLOW_MS` (`5000`): with the memory backend only, an aggregate search whose query contains the term waits this many milliseconds first, to simulate a cold search in the end-to-end tests.

## Related settings

- **Web app build-time variables** (`VITE_*`, the dev server's API origin): [`web/README.md`](../../web/README.md).
- **Ingest pipeline** (`usnm-ingest`): the store, state and index-target options also read environment variables (`USNM_CURATED_URL`, `USNM_REFERENCE_URL`, `USNM_COSMOS_ENDPOINT`, `USNM_QUICKWIT_*`, …); see `usnm-ingest --help` and [Development](development.md#ingest-pipeline). The release's layout settings for a full rebuild (`--partition-decade`, `--single-text-field`, `--page-language`) come from the deployment settings `USNM_PARTITION_DECADE`, `USNM_SINGLE_TEXT_FIELD` and `USNM_PAGE_LANGUAGE` ([operations](../operations/rebuild-and-index-storage.md#full-rebuild)).
- **Deployment settings**, which `infra/main.bicepparam` reads and turns into the variables above for each environment. The public ones are committed in `infra/env/<env>.json`. The private ones (addresses, principals, resource ids) are in the settings store, an App Configuration store shared by the subscription's environments, under the environment's label. The stack's outputs and identifiers stay in the local file (`~/.config/usnewsmap/<env>/.env` when that directory exists, otherwise `.azure/<env>/.env`). `infra/env/schema.json` says where each setting lives; [`infra/README.md`](../../infra/README.md#settings-and-the-deployment-stack) and [operations](../operations/environments-and-deploys.md#settings) say how to change one. Two of them shape the API's capacity:
  - `USNM_API_MAX_REPLICAS` (default `2`, at least 1) is the API's scale maximum and the divisor for shared-searcher slots above. Azure may run fewer.
  - `USNM_SEARCHER_APP_RETAIN` (default `false`) keeps the searcher app and its reader role while `USNM_SEARCHER_APP` is off and the API goes back to its sidecar. It doesn't change API routing. Clear it when the sidecar revision is ready and serving ([the two-step rollback](../operations/search-serving.md#searcher-app)).
