# OCR candidate feasibility notes — 2026-10-18

This is the independent feasibility portion of [#812](https://github.com/tgoodyear/usnewsmap.com/issues/812). It does not implement or reproduce #810's refreshed-LoC paired protocol. The adapter from #810's merged PR [#816](https://github.com/tgoodyear/usnewsmap.com/pull/816) is available, but #810 reports no verified scan/reference overlap yet, so no paired refreshed-LoC score is possible. No paid resources were used; the bounded CHURRO trial used the already-owned pve-big GPU under #794 coordination.

## Bounded local CPU trial

All outputs were generated from the exact pinned v1.0.0 smoke members above. German `line-pair` images were processed as one block (`--psm 6`); the initial single-line mode was not used for scoring. `deu_frak` used `--oem 0`, while the other Tesseract runs used the installed LSTM engine. Keep it in the candidate set pending the proper paired, stratified evaluation. ### CHURRO 3B

The exact checkpoint is `stanford-oval/churro-3B` revision `ca2150ea465d5a3d67818c50e234b9422619c75d`; its 7,509,337,944-byte weights are under the Qwen Research License (non-commercial research/evaluation only). The license permits distribution of its materials with its notice/attribution conditions and does not state a blanket prohibition on ordinary OCR-output redistribution; clause 4(b) requires “Built with Qwen”/“Improved using Qwen” only when outputs are used to train, fine-tune or improve a distributed AI model. This use falls within the maintainer's authorization. The project source list overlaps at collection level with Chronicling America/American Stories and Reichsanzeiger-GT; exact page exposure is unknown.

A single bounded GPU trial ran on 2026-10-18 after #559's explicit handoff and fresh host/CT214 idle checks. The exact model tree has digest `0136091efd1189d23893f04b9118c9f6ecb98793c108b36655e9894ac72c2603`; CHURRO code was pinned to `stanford-oval/Churro` commit `23c3ac65781443b18d87c8cdac5f77445c3319e6`. It used the official 0.3.0 Hugging Face profile `CHURRO_3B_XML_TEMPLATE`, deterministic decoding, FP16 without quantization, a 6-GiB GPU/9-GiB CPU placement cap, and `max_new_tokens=4096`. Runtime was Python 3.13.5, PyTorch 2.14.1+cu126, Transformers 5.20.1, and Accelerate 1.15.0. The RTX 2060 SUPER has 8 GiB VRAM; layers 0–27 were placed on GPU and layers 28–35 plus normalization on CPU. The trial did not modify BOINC tasks, queues, preferences, caches, or services; the GPU was idle again immediately after completion.

The OCR loop took 926.040 s for ten images (0.65 images/min); first image 97.404 s, warm median 88.878 s and p95 107.916 s. Runtime import, processor load, and model load took 7.125 s, 1.070 s, and 12.287 s. Every output was nonblank; no sample reached the token cap (largest generation 316 tokens). PyTorch peak allocated/reserved GPU memory was 6,404,122,624 / 6,455,033,856 bytes. The process peak RSS was 9,285,700 KiB (8.85 GiB); there was no cgroup memory limit. The exact generated XML is preserved separately; scoring text excludes the non-OCR `<Metadata>` subtree, ignores formatting-only XML indentation, normalizes whitespace between inline OCR elements to one space, unescapes XML text, and preserves line breaks. There is no OCR post-correction. The original receipt names the intended CHURRO source revision but does not attest the installed import path or checkout cleanliness; those fields are marked unverified. The runner now verifies Git HEAD, a clean checkout, tracked import path in the checkout, and the locked `churro-ocr` version before inference.

The official package's ONNX pipeline ran full English crop inputs with line detection, localizer, word/character recognition, 0.83 word-similarity cutoff and no post-correction.
