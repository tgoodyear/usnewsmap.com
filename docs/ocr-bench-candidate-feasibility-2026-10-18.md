# OCR candidate feasibility notes — 2026-10-18

This is the independent feasibility portion of [#812](https://github.com/tgoodyear/usnewsmap.com/issues/812). It does not implement or reproduce #810's refreshed-LoC paired protocol. The adapter from #810's merged PR [#816](https://github.com/tgoodyear/usnewsmap.com/pull/816) is available, but #810 reports no verified scan/reference overlap yet, so no paired refreshed-LoC score is possible. No GPU hosts or paid resources were used.

## Inputs and machine

- Benchmark: verified public release `ocr-bench-v1.0.0`, archive SHA-256 `4835d64e5607b1642290102bcaf02ebc807237931a187b25aea162195ea60a42`; content digest `c5e38736b6e60610ef0dbe6d8296c3dc58f8a945d6e1cfea5aa47b03fb163800`; fetched and verified on 2026-10-18 with `scripts/ocr-bench/fetch --version v1.0.0 --verify`.
- `overproof-en/smoke-10`: 10 images, 9 source pages, subset digest `e4256f3e6c9ae9e0453e74d7b38c5c862e8265ab88a50ca95dd3fbfd8fd10576`.
- `reichsanzeiger-de/smoke-10`: 10 line-pair images, 8 source pages, subset digest `0aa2c383e04e0d2709ec11faedd8a6d2bdc1850430ca3e8ea6efc68e2239b695`.
- Local CPU only: Apple M1 MacBook Air, 8 CPU cores, 16 GiB unified memory, macOS 27.0. Tesseract 5.5.1 / Leptonica 1.87.0. No cgroup interface is available on macOS.
- All v1.0.0 samples are public evaluation data, not held-out test data. These ten-sample smoke results are feasibility evidence only, not a leaderboard or a conclusion about generalization.

The trial outputs and model downloads stayed local and are not committed. The output JSONL SHA-256 values below lock the exact generated output bytes; references and output text are not duplicated here. The release's original sample hashes were checked before inference, and the repository's canonical `bench-score` command produced the scores.

## Bounded local CPU trial

All outputs were generated from the exact pinned v1.0.0 smoke members above. German `line-pair` images were processed as one block (`--psm 6`); the initial single-line mode was not used for scoring. `deu_frak` used `--oem 0`, while the other Tesseract runs used the installed LSTM engine. English crops used the same block mode. Each Tesseract invocation was a fresh process, so cold wall times include process startup and model load; warm, persistent-process latency was not measured. The two scoring-rule rows for each model use byte-identical OCR output (same hash); their different wall times are repeat-to-repeat cold-run variation, not a scoring-rule effect. Throughput is calculated for each timed ten-unit pass as `600 / wall-seconds` and rounded to the nearest whole unit/minute. The `deu_frak` raw-v1 row reuses the same measured inference pass as its legacy-ws-v1 row. The English `eng` model was the locally installed Homebrew data file (SHA-256 `7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2`). German models and outputs are pinned above.

Empty predictions are counted separately from missing output records. All ten outputs were present and nonempty per model; character omissions and historical glyph substitutions remain included in CER. The German references contain 14 long-s (`ſ`), two currency glyphs (`ℳ`) and four historical hyphen glyphs (`⸗`) across these ten samples; no special-character weighting was added.

The legacy Fraktur model `deu_frak` is 34.08 CER percentage points worse than ordinary German `deu` on this smoke subset and has about half its throughput. **Tentative keep/drop:** drop this old `deu_frak` engine/model combination from the next candidate set unless a newer checkpoint is identified. `deu_latf` is the German LSTM Fraktur candidate, formerly known as `frk`; it scored 2.23 CER percentage points worse than `deu` on these ten samples. This is evidence about that candidate on this smoke subset, not a broad Fraktur-only accuracy claim or a paired comparison. Keep it in the candidate set pending the proper paired, stratified evaluation. At the initial feasibility cutoff, the Calamari trial was inconclusive and no CHURRO, EffOCR, docTR, Qwen, or refreshed-LoC outputs had been generated; the later valid Calamari trial is recorded below. No American Stories samples are in v1.0.0 (its sources are Overproof/Chronicling America and Reichsanzeiger).

### CHURRO 3B

The exact checkpoint is `stanford-oval/churro-3B` revision `ca2150ea465d5a3d67818c50e234b9422619c75d`; its 7,509,337,944-byte weights are under the Qwen Research License (non-commercial research/evaluation only). The license permits distribution of its materials with its notice/attribution conditions and does not state a blanket prohibition on ordinary OCR-output redistribution; clause 4(b) requires “Built with Qwen”/“Improved using Qwen” only when outputs are used to train, fine-tune or improve a distributed AI model. This use falls within the maintainer's authorization. The project source list overlaps at collection level with Chronicling America/American Stories and Reichsanzeiger-GT; exact page exposure is unknown.

A single bounded GPU trial ran on 2026-10-18 after #559's explicit handoff and fresh host/CT214 idle checks. The exact model tree has digest `0136091efd1189d23893f04b9118c9f6ecb98793c108b36655e9894ac72c2603`; CHURRO code was pinned to `stanford-oval/Churro` commit `23c3ac65781443b18d87c8cdac5f77445c3319e6`. It used the official 0.3.0 Hugging Face profile `CHURRO_3B_XML_TEMPLATE`, deterministic decoding, FP16 without quantization, a 6-GiB GPU/9-GiB CPU placement cap, and `max_new_tokens=4096`. Runtime was Python 3.13.5, PyTorch 2.14.1+cu126, Transformers 5.20.1, and Accelerate 1.15.0. The RTX 2060 SUPER has 8 GiB VRAM; layers 0–27 were placed on GPU and layers 28–35 plus normalization on CPU. The trial did not modify BOINC tasks, queues, preferences, caches, or services; the GPU was idle again immediately after completion.

The OCR loop took 926.040 s for ten images (0.65 images/min); first image 97.404 s, warm median 88.878 s and p95 107.916 s. Runtime import, processor load, and model load took 7.125 s, 1.070 s, and 12.287 s. Every output was nonblank; no sample reached the token cap (largest generation 316 tokens). PyTorch peak allocated/reserved GPU memory was 6,404,122,624 / 6,455,033,856 bytes. The process peak RSS was 9,285,700 KiB (8.85 GiB); there was no cgroup memory limit. The exact generated XML is preserved separately; scoring text excludes the non-OCR `<Metadata>` subtree, ignores formatting-only XML whitespace, unescapes XML text, and preserves line breaks. There is no OCR post-correction.

The adapter now records the selected executable hash on future runs; that hash alone does not attest to the upstream source revision or license. The five-voter model is pinned to `Calamari-OCR/calamari_models` commit `308697f2fe2f0143d687107e6157688ea4116157`; the adapter fails closed unless its computed model-tree digest matches the committed `c8d3b6e7819f8300e308016bf4e959fdaefd71836ee3b9d7d2f164ca9412d628` lock.
