# BUDA evaluation: validation, worker identity and Mac support

**Status:** accepted no-migration decision; server spike not run · **Decision:** 2026-10-16 · **Measured on:** BOINC `22bbebe08e2eaac5d5e88a6d93b88e800cb6341c`, wiki `7e16379966f15b9be85fc6206f875e02c70d6bc0`, docker_wrapper release 22 · **Issue:** [#481](https://github.com/tgoodyear/usnewsmap.com/issues/481)

## The question

Follow-up: [Mac tests without a project server](2026-10-14-buda-mac-offline-tests.md) records installation, standalone container execution and failures. It also corrects this note's initial conclusion that Podman was absent: Podman was already installed outside the checked PATH; BOINC's required Mac helper was missing.

Can BUDA replace the three signed Docker-wrapper apps while preserving their validation, worker image pins and the bridge's native publication/recovery contract? The accepted decision is [ADR-0020](../design/adr/0020-boinc-buda-evaluation.md). The [spike procedure](../experiments/2026-10-14-buda/README.md) records the live acceptance tests that remain blocked and would require a new decision to resume.

## What we checked

The repository's base Containerfile pins upstream BOINC at `22bbebe08e2eaac5d5e88a6d93b88e800cb6341c`. BUDA's web pages, scheduler code, local debugging tool, generic remote submission handler and script validators are already present at this commit. No newer server source is necessary merely to expose those features; the running image and project upgrade still need checking. A cross-check of current upstream documentation and scheduler code at `38dba984c34a3d454a466636cac8e94594b7a0d8` found the same model: one trivial validator, workunit-delivered variant files and client-side Docker builds, with no per-variant validation, BOINC app-version signature for variant files or required image digest.

## What is left

The accepted [ADR-0020](../design/adr/0020-boinc-buda-evaluation.md) is a no-migration decision based on the reviewed implementation's validation, code-authorization and mutable-variant gaps; it is not evidence that a live BUDA task passed or failed. No `buda` app was registered as part of this evaluation, and no web batch, remote submission, custom validator, signed distribution, Linux client task or Mac client task was run. Server, database and signing-host access were unavailable. Keep the existing three apps and daemons unchanged. The [spike procedure](../experiments/2026-10-14-buda/README.md) is retained only for reconsideration after those architectural gaps are resolved and a new decision authorizes a test.

Current volunteer attachment state could not be verified: the public project's DNS name did not resolve from this environment, and no server/database access was available. The issue's initial statement that no volunteers had attached is therefore not a current count; PR [#500](https://github.com/tgoodyear/usnewsmap.com/pull/500) reports an operator test-client attachment, but does not establish current volunteer totals. Keep #481 open for the blocked live acceptance checks and do not treat this source-based decision as completing them.
