# Sample page ids on the Qwen wire: inventory and an additive encoding

**Status:** shipped in `usnm-boinc` (opt-in; no worker, image or bridge change) · **Date:** November 2026 · **Measured on:** `main` at c6b667dd, the `bundle-v1` and `bundle-v2` gold locks · **Code:** `crates/usnm-boinc/src/qwen/doc_id.rs`, `qwen/benchmark.rs`, ADR-0026 · **Issues:** #983

## The question

[ADR-0026](../design/adr/0026-source-qualified-page-ids.md) names a dataset sample `sample:<dataset>/<sample id>`. `PageId` (`usnm-core/src/page_id.rs`), the Congress adapter and Surya's qualified staging (#995) already use it. Three places still don't: Qwen benchmark staging writes `benchmark-<sha256 of the crop id>`, gold bundle crops have bare ids, and the data catalog checks the `<source>:` prefix only loosely.

The Qwen worker is the hard case. Every released `usnm_qwen` build runs `Job::validate`, which checks `Job.doc_id` and each bundle page's `doc_id` with `quality::check_doc_id`: 1 to 128 bytes of `[A-Za-z0-9_-]`. `sample:bln600/pub-bln600-063` fails that check, so putting it on the wire would mean a new request version and a new signed release. Old campaign directories and signed jobs can't be rewritten either. This note records every place these identities are made or read, and the part that could land without changing what a deployed worker accepts.

## What we did

**A wire spelling for samples that released workers already accept** (`qwen::doc_id`). A Qwen `doc_id` is now read as one of three forms, and nothing else:

- a LoC page: its bare `doc_id`, unchanged;
- a dataset sample: `sample-<dataset>_<sample id>`. A sample id's `_` is written `_5F` and its `.` is written `_2E`, in upper-case hex. Every other byte a sample id can hold is already in `[A-Za-z0-9-]` and is written as it is;
- a legacy benchmark crop: `benchmark-` and 64 lower-case hex digits.

The mapping from a `sample` `PageId` is reversible, and the reader takes only the canonical spelling: it decodes, builds the `PageId`, spells it again and compares. It never hashes or shortens. A sample whose spelling is longer than 128 bytes has no wire id and is refused, as is any source other than `loc` and `sample`.

**Collision rules.** No two pages share a wire id, and the three forms can't be confused:

- A dataset is `[a-z0-9][a-z0-9-]{0,39}` and has no `_`, so the first `_` after `sample-` ends the dataset and every later `_` begins an escape. `sample:a-b/c` and `sample:a/b-c` are `sample-a-b_c` and `sample-a_b-c`.
- A LoC `doc_id` starts with its LCCN, `[a-z0-9]{1,16}`, up to its first `_`. A sample or legacy id has a `-` before any `_`, so neither reads as LoC.
- A legacy id has no `_`, and `sample-` and `benchmark-` differ.
- No form holds a `:`, so a bundle's `<doc_id>:<crop id>` still splits at its one `:`. The unchanged `split_once(':')` stays exact under version 1: crop ids pass `check_name`, so they never hold a `:` either.

**One producer, opt-in.** `qwen benchmark-stage --doc-ids sample` names each crop `sample-<source_dataset>_<crop id>`, from the dataset its manifest row already carries. It fails if the row has no valid `source_dataset`. The default, `--doc-ids legacy`, writes exactly what it wrote before; a test pins the hash for a known crop id. A campaign keeps the spelling it was staged with: staging an existing root with the other spelling changes every job, and the existing immutability check refuses it ("use a new --root"). The manifest's `v` stays 1 and its schema is unchanged.

**Collection checks the id.** `benchmark-collect` now reads each job's `doc_id` and refuses one that doesn't name the entry's crop. A legacy id must be the crop id's hash, and a sample id must name both the crop's dataset and its id. A LoC id or a foreign spelling is refused. Every campaign staged so far uses the legacy spelling, so each one still collects, and a campaign of either spelling collects with the same code.

Nothing else changed. The contract crate, the worker, its request version, the bridge, the gold bundle and its lock, Iris and the data catalog are as they were. Only `usnm-boinc` changed. The images built from it are published only when their workflows are dispatched, so merging this publishes and deploys nothing.

## What is left

These need an owner's decision, and none of them is needed to keep current campaigns running.

1. **Switch the bridge's Qwen benchmark staging.** Pass a new bridge variable, `QWEN_DOC_IDS` (default `legacy`), as `--doc-ids` to the two `qwen benchmark-stage` calls in `contrib-compute/images/server/bridge-job.sh` (`qwen-benchmark-prepare` and `qwen-benchmark-stage`), and set it to `sample` only for a new `QWEN_CAMPAIGN`. Then rebuild and install the bridge image through its existing dispatch workflow. The deployed workers need no change. Existing campaigns, such as `transcription-baseline-v1`, keep their legacy ids: re-staging one with `sample` is refused, never rewritten, which is why the default should stay `legacy` until no legacy campaign needs re-staging.
2. **Qualified ids in the Qwen contract itself.** Only if `sample:` must appear verbatim on the wire: a request version 2 whose doc id check accepts the `PageId` grammar, while version 1 keeps `check_doc_id`. Bundle crops would then split at the last `:`, since crop ids hold none. That means a new `usnm_qwen` build signed and released for every platform. The encoding here makes that unnecessary for the current sources.
3. **Gold bundle v3.** Gold crop ids are inside the digest-pinned bundle and returned by the signed gold worker, so qualifying them means a new bundle version and lock, not a change to v1 or v2. Each crop's `source` already gives the qualified form, `sample:<source>/<crop_id>`.
4. **The data catalog.** Check a `page_id`'s source against ADR-0026's registry, through `PageId` or a generated copy of its rules, before a source other than `loc` is written there.
5. **Local benchmark slots.** `usnm-ocr-survey` `qwen_bench` could use the same spelling, but a release's sample ids may hold `/`, which a single-segment `sample` id doesn't allow. That needs a rule for multi-part sample ids first.
