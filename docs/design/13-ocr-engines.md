# 13: OCR Engines

**Status (10 November 2026):** designed in October 2026 with [ADR-0016](adr/0016-pluggable-ocr-engines.md) for the on-prem queue worker, which is retired (#966, #1053). OCR now runs only through BOINC ([BOINC pages](../boinc/README.md)): `usnm_ocr` reads Latin-script pages with the pinned Tesseract image directly, without the contract, and `usnm_ndlocr` reads Japanese pages through the NDLOCR-Lite contract adapter. A section says when it describes the retired worker. **Pipeline:** [12: On-prem OCR pipeline](12-onprem-ocr-pipeline.md).

This document covers how engines plug in: the contract, limits, routing, provenance, the survey, and an engine catalog. [12](12-onprem-ocr-pipeline.md) specifies the rest under its step names: worker build (Step 2), `usnm_core::lang` and `usnm_core::damage` (Steps 4 to 6), message validation (Step 7), `usnm-ingest ocr-sync` (Step 8), the release (Step 9), the seeder (Step 10).

## 13.1 Scope and terms

- **Engine:** an OCR program and its models. **Family:** the program (`tesseract`, `kraken`); it names `ocr_source` (`usnm-<family>`).
- **Engine id:** family plus major.minor (`tesseract-5.5`). A new engine version, adapter or model set is a new image digest under the same id; a new major.minor is a new id.
- **Engine image:** OCI image with engine, models and adapter, pinned by digest. **Adapter:** the entrypoint that speaks the contract. **Instance:** a running container, one page at a time.
- **Profile:** a named model set plus settings (`deu_latf+deu`). **Route:** a rule in `ocr/routing/routes.toml` mapping a page to engine and profile.
- **Worker:** the program that reads a page and writes its outputs: `usnm-boinc work` inside `usnm_ocr` and `usnm_ndlocr`, `usnm-ocr-worker run` on the retired nodes. **Engine host:** the code that runs contract instances (`usnm_ocr_worker::contract`).

## 13.3 Component view

**History (worker retired, #966).** One node held the worker and its engine instances; the private Azure registry (engine images by digest), loc.gov and tile.loc.gov, and the exchange account were outside. The worker ran as `usnm` (in `himds`, so it could get Arc tokens) and never ran podman locally: engines ran rootless under a separate `usnmeng` account outside `himds`, driven through its Podman API socket `/run/usnm-ocr/podman.sock` (0660, group `usnmocr`) with `podman --remote`, whose `run --interactive` pipes carried the contract. That let the hardened unit set `NoNewPrivileges=yes` (ADR-0016). Scratch was a size-capped tmpfs at `/run/usnm-ocr/scratch`, so engine output counted against the engine's memory limit; each instance slot had worker-owned `in/` and `out/` with a fixed MCS label pair instead of `:Z`, and a per-page `out/<run_id>/` (0700) with an ACL for the container user. The engine-host code stays in `crates/usnm-ocr-worker`.

On BOINC the client starts the worker image in its own container (`boinc/apps/job.toml`: no network, read-only root, one CPU, 1536 MiB, 64 processes) and the worker runs Tesseract inside it, so the instance pool and Podman socket aren't used ([worker image](../boinc/apps/worker-image.md)).

## 13.4 The contract (usnm-ocr-engine/1)

### 13.4.1 Framing

- The adapter is the `ENTRYPOINT`, started with `--contract 1 --threads <n>`.
- Requests on stdin, replies on stdout: one JSON object per line, UTF-8, LF, at most 1 MiB. One request in flight per instance.
- stderr is free-form. The worker reads it continuously in lines of at most 4 KiB, drops and counts lines over a rate limit, and never stalls on it (podman's attach multiplexes both streams). It keeps the last 50 lines for failure reports and never parses them.
- Within a major version, readers ignore unknown fields; an optional field doesn't bump the version. EOF on stdin: finish, exit 0.
- No bulk data on the pipes. The worker writes `/in/<run_id>.jpg` (`.png` if scaled or tiled, §13.4.3) and creates `/out/<run_id>/`; the adapter writes only regular files, mode 0644, directly in it, and names them in its reply.
- A non-contract stdout line is a crash: kill and restart.
- Python adapters dup fd 1 for the protocol before importing the engine, then point fd 1 and `sys.stdout` at stderr. Rust adapters give children a null or captured stdout and their own process group (§13.6.3).

### 13.4.2 hello (adapter to worker)

First stdout line, when ready. Excerpt (German profiles of the Tesseract image as designed; the built text-only adapter is `usnm-ocr-adapter-tesseract-text`; keys sorted, as in all examples):

```json
{
  "adapter": {"lang": "rust", "name": "usnm-ocr-adapter-tesseract", "version": "0.1.0"},
  "cancel": "adapter",
  "contract": 1,
  "deterministic": true,
  "engine": {"family": "tesseract", "id": "tesseract-5.5", "version": "5.5.0"},
  "granularity": "word",
  "layout": "alto",
  "models": [
    {"name": "tessdata/deu.traineddata", "sha256": "8407331d6aa0229dc927685c01a7938fc5a641d1a9524f74838cdac599f0d06e"},
    {"name": "tessdata/deu_latf.traineddata", "sha256": "429b8c33d37e1a4823a2bb082a644ff13e252f735b7945e08a518d22ddcc459e"},
    {"name": "tessdata/frak2021.traineddata", "sha256": "1da2384254fa8462c776faf3b43307fe19ce51be0931c623b2fdd560f96e299a"}
  ],
  "models_loaded": "per_page",
  "profiles": [
    {"id": "deu", "languages": ["deu"], "models": ["tessdata/deu.traineddata"], "tunable": ["psm"]},
    {"id": "deu_latf+deu", "languages": ["deu"], "models": ["tessdata/deu_latf.traineddata", "tessdata/deu.traineddata"], "tunable": ["psm"]},
    {"id": "frak2021", "languages": ["deu"], "models": ["tessdata/frak2021.traineddata"], "tunable": ["psm"]}
  ],
  "type": "hello"
}
```

- `models`: every file any profile can load, hashed from disk at start (for a CLI engine, the files passed to the CLI). `models_loaded`: `at_start`, or `per_page` for CLI and script engines (Tesseract, Kraken CLIs), whose load time is inside `seconds_wall`.
- `cancel`: `adapter` or `kill` (§13.6.3). `languages`: ISO 639-3 (MARC is mapped before routing, §13.7.5). `layout`: `alto` or `boxes`. `granularity`: finest level with real geometry (`word`, `line`, `block`, `page`). `engine` may add `components` (e.g. Leptonica). No timing; the worker measures start to hello (`model_load_seconds`).
- The worker refuses the instance, counting toward the breaker (§13.6.4), unless the whole hello matches the lock entry for the digest (§13.7.3): `adapter`, `contract`, `engine` (with `components`), `cancel`, `deterministic`, `granularity`, `layout`, `models_loaded`; the (name, sha256) set; and every profile's `languages`, `models` and `tunable` as sets. A different `engine.version` would write an unreviewed version into `ocr_engine`; a different `cancel` changes timeout handling; a profile that kept its id but changed models or languages would draw `unsupported` replies and a wrong `models_digest`. CI writes the lock entry from hello (§13.7.3).

### 13.4.3 page (worker to adapter)

```json
{
  "deadline_ms": 840000,
  "image": {"dpi": 300, "dpi_source": "assumed", "height": 7208, "path": "/in/node1.20261020T140312123456Z.jpg", "sha256": "<sha256 of the file>", "width": 5412},
  "language": "deu",
  "options": {"psm": 3},
  "out": "/out/node1.20261020T140312123456Z/",
  "profile": "deu_latf+deu",
  "run_id": "node1.20261020T140312123456Z",
  "script": "Latf",
  "type": "page"
}
```

- `run_id` is `<node>.<UTC stamp>`, minted at page start before the engine call (`provenance::mint_run_id`, #307); it names the ALTO, runs record and overlay part. No `doc_id`, URL, batch or credential is sent; the worker logs `run_id` to page.
- **Options:** profile `defaults` from `engines.toml` overlaid by the candidate's `options`, sent merged and recorded in the runs record and ALTO. Only keys in the profile's `tunable` may be set. Worker preprocessing (`scale`, `tile`) has its own keys.
- **Image and dpi.** The worker decodes the whole scan (Rust `image` crate) first. Cached scans may be the batch's JP2 since #368 (12 §12.2.4), which `image` can't read; until an OpenJPEG decoder or PNG conversion exists, only Tesseract (JP2 via Leptonica) gets them. `image.dpi` is the scan's dpi times `scale` (300 full, 150 half); adapters take dpi only from here (it isn't an option), and the Tesseract adapter passes it as `--dpi`, so every route reads full scans at 300 dpi, as the BOINC worker does. It passes `--dpi 300` always, since IIIF JPEGs carry no resolution and Tesseract would guess 70.
- **Scale** is worker preprocessing, never in `options`, `tunable` or hello. A profile may set it beside `tile`, and a candidate may override it with its own `scale` (default 1). The worker resizes with Lanczos3 and writes PNG to avoid re-encoding JPEG; the path's extension gives the format, `image.*` describes the scaled file, boxes are scaled back, and the runs record has a `scale` column.
- **Tiles:** a profile may set `tile = { size = 1280, overlap = 256 }` (the survey runs docTR and Surya this way). Each tile is its own request to one instance in turn, `run_id` `<run_id>.t<n>`, own `out`, `deadline_ms` the time left. `usnm-alto` moves boxes to page pixels and keeps a box only if its centre is in the tile's core (tile less half the overlap on inner edges), as the survey's `inside()`. The page is `ok` only if every tile is. Adapters never tile or merge tiles.
- `script`: ISO 15924, optional. `dpi_source`: `assumed` or `loc_alto` (dpi read from LoC's ALTO).

### 13.4.4 result (adapter to worker)

```json
{
  "engine_stats": {"mean_conf": 0.71, "words": 6034},
  "layout": {"kind": "alto", "path": "/out/node1.20261020T140312123456Z/page.xml"},
  "markup": "none",
  "run_id": "node1.20261020T140312123456Z",
  "status": "ok",
  "text": {"path": "/out/node1.20261020T140312123456Z/page.txt"},
  "type": "result",
  "warnings": []
}
```

- `layout.kind` (`alto`, any version and `MeasurementUnit`, or `boxes`, §13.4.5) must equal hello's `layout`; boxes must declare hello's `granularity`, and ALTO must have geometry at it. Mismatch: `engine_protocol`. ALTO results add `alto_dpi` when the engine converted pixels at an assumed dpi (NDNP Open OCR at 300).
- `text` is the engine's own text, kept only for survey comparison; stored text is derived from the layout (§13.4.7). Block-level engines put block text in `boxes.json`; page-level engines write one page-sized block.
- `markup`: `none`, `html` (Surya) or `markdown` (most vision-language models), stripped once in Rust before the ALTO writer and `normalize_ocr`. Ordered list markers always stay; a bullet goes only when at least two adjacent lines start with it, each before an item starting with neither a number nor a currency sign, because lines like `31. Dezember` and `- 5 Cents` are text (#1488). Other formats (DocTags, grounding tokens) are parsed by the adapter into boxes and one of these three values (the Rust `openai-vlm` per-model parsers).
- `status`: `ok`, `unsupported`, `bad_input`, `failed`, `timeout` (§13.4.6). Failures add `"error": {"kind": "...", "message": "..."}` (at most 2 KiB, never page text); `failed` may add `"restart": true` when the adapter knows its engine is in a bad state.
- `"partial": true` output (text read before a deadline) is survey-only; production never stores it.
- `engine_stats`: at most 64 numeric keys of at most 64 characters, stored uninterpreted in `engine_stats_json`, keys sorted. Adapters never report timings, resources, digests or damage.

### 13.4.5 boxes.json (usnm-boxes/1)

For engines without ALTO: docTR, OnnxTR, American Stories, Surya, NDLOCR-Lite, PaddleOCR, oar-ocr, and vision-language spotting or grounding output.

```json
{
  "blocks": [
    {"bbox": [120, 340, 1610, 2200], "conf": 0.9, "dir": "ltr", "kind": "text", "label": "article", "lang": "deu", "lines": [
      {"bbox": [120, 340, 1610, 395], "conf": 0.87, "hyphen": false, "text": "Deutsche Zeitung", "words": [
        {"bbox": [120, 342, 410, 395], "conf": 0.91, "text": "Deutsche"}
      ]}
    ], "order": 0},
    {"bbox": [1700, 300, 3400, 1900], "kind": "illustration", "order": 1}
  ],
  "frame": {"height": 7208, "width": 5412},
  "granularity": "word",
  "reading_order": "engine",
  "units": "px",
  "v": 1
}
```

- `units`: `px`, `rel` (0 to 1, docTR) or `norm1000` (Qwen3-VL, LightOnOCR, Chandra, HunyuanOCR). `frame` is the size the coordinates refer to; an internally resizing engine (dots.ocr) reports `px` with its resized `frame`. Rust maps to the sent image, then the full IIIF frame.
- Boxes are `[x0, y0, x1, y1]` from top left with `x1 > x0`, `y1 > y0`; optional `polygon` and `baseline` as lists of `[x, y]` points. Up to 2 px outside the frame is clamped; more is `convert`.
- `kind`: `text`, `heading`, `caption`, `table` (TextBlocks), `illustration` (Illustration, any text on it dropped), `separator` (GraphicalElement).
- `reading_order`: `engine` (array order or block `order`) or `none` (detection or tile order: docTR, PaddleOCR), for which Rust orders blocks by a column-aware XY cut in the page's direction, so 6 to 8 column pages aren't read across.
- `dir` on block or line: `ltr`, `rtl`, `ttb-rl` (NDLOCR-Lite vertical Japanese); default by script (`rtl` for Hebrew and Yiddish, `ltr` otherwise); words in a line and lines in a block are ordered by it. Lines in a block go in rows top to bottom (right to left for `ttb-rl`), each row along the direction, so a detector's segments of one printed line read in order. Two lines share a row when their cross-line extents overlap by more than half the smaller and their along-line overlap is at most half the shorter; every pair in a row must qualify, so overlap chains can't merge a column into one row.
- Text sits at the finest level present. `hyphen: true` marks a word continued on the next line; the writer emits `HYP` and, where it can join the parts, `SUBS_CONTENT`. `conf` is 0 to 1 or absent.

### 13.4.6 Status and what the worker does

The Production column is the retired queue worker's handling (#966). Under BOINC a failed page is returned as failed; the controller retries or dead-letters it ([a page that fails for good](../boinc/server/batch-scheduler.md#a-page-that-fails-for-good)), and a bundle's other pages still count ([OCR bundles](../boinc/apps/ocr-bundles.md)).

| Source  | Status                                                                                         | Production (worker)                                                                                                          |
| ------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| adapter | `ok`                                                                                           | Convert, write the outputs, delete the message                                                                               |
| adapter | `unsupported`: profile, language or option not in this image                                   | Next candidate, same receive. None left: transient `no_model`, logged as a routing error                                     |
| adapter | `bad_input`: the engine can't read an image the worker decoded                                 | Adapter fault: transient `engine`, next candidate in the same receive                                                        |
| adapter | `failed`                                                                                       | Transient `engine`; restart if asked                                                                                         |
| adapter | `timeout`: the adapter stopped at `deadline_ms` and stopped its processes (`cancel = adapter`) | Transient `engine_timeout`; recycle if `cgroup.procs` has processes not there after `hello`                                  |
| worker  | the scan doesn't decode                                                                        | Permanent, dead-lettered; no engine called                                                                                   |
| worker  | no result by `deadline_ms` + 15 s                                                              | Kill; transient `engine_timeout`; restart lazily                                                                             |
| worker  | instance exited, or a stdout line that isn't contract JSON                                     | `engine_oom` if `podman --remote inspect` shows `OOMKilled`, else `engine_crash`; `podman --remote rm`; restart with backoff |
| worker  | protocol: a limit, a path or the schema broken                                                 | Transient `engine_protocol`; replace the instance                                                                            |
| worker  | `convert`: the ALTO or boxes don't parse                                                       | Transient `convert`                                                                                                          |
| worker  | no usable candidate on this node                                                               | Transient `no_route_here`, plus a node-wide receive backoff (§13.7.6)                                                        |

The survey records every outcome, scoring `ok` and keeping partial text on `timeout`.

On the worker, transient left the message to reappear after its visibility timeout, permanent went to `ocr-deadletter` at once, and a message received more than 5 times was dead-lettered. Repeated failures were to move a page to the next candidate by dequeue count (§13.7.6).

### 13.4.7 What the worker does with a result

1. **Checks files.** Paths must resolve inside `out/<run_id>/`, with no `..` or symlinks (`symlink_metadata`, `O_NOFOLLOW`), and be regular files. Caps: result line 1 MiB, ALTO or boxes 64 MiB, text 8 MiB, job directory 256 MiB (larger than step 7's output limits, because engine ALTO is more verbose than the stored ALTO).
2. **Parses.** `usnm-alto` reads ALTO v2 to v4 in `pixel`, `inch1200` or `mm10` with quick-xml: no `DOCTYPE`, no entity expansion, caps on depth, element count, `CONTENT` length (1 KiB) and strings per page (500,000); Kraken's v4 (`SP` as sibling, polygons) is handled. JSON has a depth limit and checked UTF-8. `boxes.json` is streamed and stops at the first limit: 20,000 blocks, 200,000 lines, 500,000 words (the ALTO string cap), 1 KiB text per word or line, 512 KiB per block (step 7's stored-text limit), 1,000 points per polygon or baseline, 2,000,000 points total. The worker has no memory limit beyond its unit's, so expansion must be refused while reading. Breaches are `engine_protocol`.
3. **Writes the stored ALTO** from parsed values; only escaped `CONTENT` comes from the engine (§13.8.2).
4. **Derives the text** from the stored ALTO in reading order (port of `altotext.py`) for every granularity, so text and boxes always agree, markup already stripped, then `usnm_core::text::normalize_ocr_for`, which also rejoins an em dash at a line end on German pages or Fraktur models (`Hyphenation::for_page`, #1065). The overlay stores and the survey scores this text. Order is the engine's: where Tesseract missed a narrow unruled gutter, text runs across columns (#925). `usnm_alto::split_columns` repairs that (cuts lines straddling a gutter by word centre, reads column by column) but isn't in this step yet; `usnm-ocr-worker column-text` runs it offline on stored ALTO ([note](../notes/2026-11-05-column-reading-order.md)).
5. **Scores damage** with `usnm_core::damage` (12 Step 5) in forced-language mode, as `score.py` calls `quality.py`'s `damage()` (v2 detection needs catalog languages the worker lacks). `usnm_core::lang` maps to the metric's MARC-keyed tables (`ger` to `de`, `hrv` and `srp` to `sh`). `damage_after` is null for `jpn` (`quality.py` doesn't score Japanese titles), `und` and languages without a word list.
6. **Measures** wall, CPU, peak memory and OOM kills from the cgroup (§13.6.4).
7. **Checks output limits, then writes** ALTO, runs record, overlay part, create-only, same `run_id` (§13.8). Limits are `ocr-sync`'s (12 Step 8 checks 1 and 4), one set of constants in `usnm-ocr-contract` that `ocr-sync` uses too, so an uploaded page can't be quarantined for its size: ALTO 32 MiB, part and runs record 1 MiB each, text 512 KiB with no control characters but newline and tab. Over a limit, nothing is uploaded and the page fails transient `convert`, kind `too_large`, so it can move to the next candidate. The BOINC worker applies its own caps (`boinc::MAX_TEXT`, `boinc::MAX_ALTO`) and `usnm_alto::check` before returning a page.

### 13.4.8 Versioning and conformance

- `usnm-ocr-contract`'s Rust types are the source; a schema binary writes `ocr/contract/v1/{hello,page,result,boxes}.schema.json`, and CI fails on drift.
- A breaking change is contract 2; the worker supports N and N-1 during migration, and conformance tests both. CI will run conformance on every image it builds.
- `usnm-ocr-worker engines conformance --engine <id> --fixtures ocr/contract/fixtures`. Until `engines.toml` names engines by id (#371) the form is `--engine contract` with `--engine-image` (through the engine runtime) or `--engine-command` (local adapter), `--fixtures` defaulting to `ocr/contract/fixtures`. It starts one instance at `image.dpi` 300, prints one JSON line per case (`pass`, `fail`, `skipped`) and a summary, and exits non-zero on any failure.

Built in #307 (§13.11 step 4). The runner lives in `usnm-ocr-worker` (`contract::conformance`) so every page goes through production's request, file checks, caps and parsing (§13.4.7 steps 1 and 2). Text is checked as stored (derived from layout); rendered pages are PNGs from `testimg::png`. Cases:

## 13.5 One page through an engine

On BOINC (`usnm-boinc work`, `crates/usnm-boinc/src/worker.rs`): the worker checks that the installed engine's version and route for the page's language (`engine::route`, or `engine::route_lines` for a Cherokee line job) match the job, checks the installed models against the job's profile digest, runs Tesseract on the scan the job names, checks the text and ALTO against the size caps and `usnm_alto::check`, and returns a result manifest with the scan, text and ALTO hashes. `collect` writes the ALTO and one-row part to `ocr-out` from the BOINC host, with no runs record ([queue-fed work](../boinc/server/batch-scheduler.md#queue-fed-work)).

The retired queue worker (#966) checked an engine was usable, received the message, validated it, minted the `run_id` and routed it; fetched the item JSON and IIIF full image and decoded, scaled or tiled it; started an instance if none was idle and checked its hello against the lock; wrote the image to `in/` and sent the page request; then either converted the result (§13.4.7), uploaded ALTO, runs record and part create-only and deleted the message, or, with no result by `deadline_ms` + 15 s, killed the instance and wrote nothing (transient `engine_timeout`). Its `deadline_ms` was the least of the engine's `page_timeout_secs`, the route's `timeout_secs`, and the page budget left minus 60 s for uploads; the budget was 0.8 of the visibility time, 1,440 s of 1,800 s. BOINC's page deadline is the job's `engine.timeout_secs` (default 1800 s, at most 3600).

## 13.6 Engine instances and resource limits

### 13.6.1 Container settings

What an engine image must work under when the engine host runs it (the retired nodes ran it this way; BOINC runs the worker image under `boinc/apps/job.toml` instead): no network (`--network=none`, only the container's loopback, where a vision-language image may run llama-server); a read-only root with a tmpfs `/tmp` (`nosuid,nodev,mode=1777`) and `HOME=/tmp`; `--no-hosts` and `--http-proxy=false`; `--ulimit nofile=1024:1024` and `--ulimit core=0`, with CPU and pid limits; `USER 10001` (`--user 10001:10001`); all capabilities dropped, no-new-privileges, default seccomp, `--init`; no swap; `OMP_THREAD_LIMIT` and `--threads` from the engine's `threads`; only the env `engines.toml` lists, with `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` and `XDG_CACHE_HOME=/tmp/cache` baked in; `/in` read-only and `/out` writable; SELinux enforcing. GPU engines get only their CDI device (`--device nvidia.com/gpu=<n>`), and GPU hosts need the `container_use_devices` boolean.

**History.** The worker started instances with `podman --remote --url unix:///run/usnm-ocr/podman.sock run --interactive --init --pull=never` plus the limits below, `--log-driver=none --stop-timeout=10` and no `--rm` (it read `{{.State.OOMKilled}}` with `podman --remote inspect` before `rm`), from a cleared environment with `HOME=/var/lib/usnm-ocr` because the podman client fails without a `HOME` (podman issues 8434, 23818).

### 13.6.2 Limits per engine

Each engine was to declare these in `engines.toml` (§13.7.2); none is in the catalog yet, and the BOINC apps take their limits from their job files:

| Field                            | Meaning                                                                             |
| -------------------------------- | ----------------------------------------------------------------------------------- |
| `memory`                         | `--memory` and `--memory-swap`. Reserved for the instance's whole life              |
| `cpus`, `threads`                | `--cpus`, and the thread count passed to the adapter and as `OMP_THREAD_LIMIT`      |
| `pids`, `shm`, `tmp`             | `--pids-limit`, `--shm-size`, and the size of `/tmp` (a tmpfs, counted in `memory`) |
| `max_instances`, `min_instances` | Instances per node, overridable per node                                            |
| `start_timeout_secs`             | Time to the `hello` line                                                            |
| `page_timeout_secs`              | Longest page                                                                        |
| `idle_stop_secs`                 | Stop an idle instance after this long (0: keep it running)                          |
| `max_jobs_per_instance`          | Recycle the instance after this many pages                                          |
| `gpus`, `gpu_memory`             | Class `gpu` only: GPUs per instance, and the GPU memory it reserves on its device   |

Profiles may add `defaults` and `tile` (§13.4.3). Starting `memory` is the survey's instance peak (`instance_peak_mem_mb`) plus 25%, rounded up; `page_timeout_secs` covers the slowest surveyed page with margin. Tesseract: 1,536 MiB, 1 CPU, 1 thread, 64 pids, 2 instances, 60 s start, 900 s page (guesses until `usnm-ocr-survey throughput`, not built, measures 2, 3 and 4 instances). `routes check` was to refuse a production engine whose `start_timeout_secs + page_timeout_secs` exceeds the page budget minus 60 s.

### 13.6.3 Deadlines and cancellation

Adapters declare `cancel` in hello, and conformance (§13.4.8) still checks it:

- **`adapter`:** at `deadline_ms` the adapter kills the process group it started for the page and cancels in-flight server requests (restarting the server if needed) before answering `timeout`, so no leftover process's CPU or memory is counted against the next page. The text-only Tesseract adapter keeps the deadline active until the child exits and both pipes reach EOF, and kills the group if they are still open.
- **`kill`:** the caller's kill is the path. Python's `SIGALRM` can't interrupt long native torch or ONNX Runtime calls, so such adapters declare `kill`; each kill costs a model load.

### 13.6.4 Node runtime (history)

The design for the worker's engine host (ADR-0016, #296), per node. Only the deadline kill and restart are in the built slice (`usnm_ocr_worker::contract`); the rest wasn't built before the nodes were retired:

- **Scheduling:** an `engine_memory` budget, allowed engines and per-engine `max_instances` from `/etc/usnm-ocr/node.toml` (node 1: 6 GiB of 8 GB); idle instance first, then a new one if it fits, then evicting idle instances of other engines; per-device `gpu_memory` budgets so CUDA OOM never surfaced as `failed`.
- **Cgroup checks:** refuse engines unless memory, cpu and pids controllers were delegated and the effective `memory.max` and `pids.max` (minimum up to the `libpod-<id>.scope`, with ancestors leaving `runtime_memory_headroom` 512 MiB and `runtime_pids_headroom` 256) matched the configured limits.
- **Failure handling:** kill at `deadline_ms` + 15 s; restart backoff 1 s, 5 s, 30 s, 2 min; recycle after `max_jobs_per_instance` pages, above 90% of the memory limit, or with leftover processes in `cgroup.procs` after a `timeout`; a breaker that opened for 15 minutes (doubling to 2 hours) after 3 crashes or refused hellos in 10 minutes, or 5 consecutive distinct pages with engine-level failures.
- **Metering:** CPU from `cpu.stat` `usage_usec`, `peak_mem_mb` from `memory.current` sampled 4 times a second, `instance_peak_mem_mb` from `memory.peak` (no per-page reset on EL9's 5.14 kernel), OOM kills from `memory.events`; telemetry `ocr.engine_seconds`, `ocr.engine_cpu_seconds`, `ocr.engine_peak_mb`, `ocr.engine_restarts`, `ocr.engine_errors`.
- **Images:** `usnm-ocr-worker engines pull --node-config /etc/usnm-ocr/node.toml` was to exchange an Arc Entra token at the registry's `/oauth2/exchange` and pull by digest, with the token in a tmpfs authfile, never on a command line; `engines gc` was to keep the current and previous bundles. The planned registry grant was AcrPull for the node group `usnm-ocr-nodes-<env>` in `infra/modules/registry.bicep`.

## 13.7 Routing

**As built.** Production routes by language in code, not through `routes.toml`: `EngineKind::for_language` sends `jpn` to NDLOCR-Lite (profile `default`) and every other language to Tesseract, and `usnm_ocr_worker::engine::route` takes the first `tesseract-5.5` profile in `engines.toml` file order that covers the language and whose models are installed and pass the licence gate ([gold check, engine routing](../boinc/server/gold-check.md#engine-routing)). A Cherokee line job (#1621) uses `route_lines`, which may also take a `lines_only` profile. `routes.toml` holds one catch-all route (`minimal`, Tesseract `auto`) that `routes check` validates. The rest of this section is the design for full routing; §13.7.2's licence gate, `profiles.lock` and catalog are built.

**One model set per profile id ([#1481](https://github.com/tgoodyear/usnewsmap.com/issues/1481)).** The engine index, API and credits page key engines by the short key, which has no model digest (§13.8.1), so any different model file (retrained or re-downloaded too) needs a new profile id: Yiddish with Jochre's model is `yid_jochre`, not a new file under `yid`.

- `ocr/engines/profiles.lock`: per engine and profile whose models are all in its `models.lock`, the sha256 of sorted `<name> <sha256>` lines (a tag's `models=` is the first 12 hex digits). `routes check` (which CI runs on the committed files in the worker's `routes_check` test) fails on a changed digest, with a message to add a new profile id, or a pinned profile without an entry; `routes check --update-lock` only appends, so dropped ids aren't reused.
- The release fails when one short key has two `models=` digests among rows read on or after 2026-11-05 00:00 UTC that replace LoC's text (`usnm_core::ocr_engine::ONE_MODEL_SET_SINCE_MICROS`): revoke the wrong rows and re-read under a new profile id. Incremental releases check rebuilt batches, full releases every row. Older rows, older tag forms and `models=local` are exempt; no pin had changed in either `models.lock` when the rule took effect.

**The gate.** `production = false` keeps an engine off production routes. Otherwise the engine's code (on `[[engine]]`, with the model fields `license`, `author`, `source`, `credit`, and `fetched`, `note`, `restricted` or `undecided` as needed) and every model of the profile must be tier 1 or 2:

1. **Cleared:** `license` in `production_licenses`.
2. **Attributed:** `license = "none"` with `source` (fetch URL), `author`, `fetched` (date), `note` (where the absence was checked) and `credit`.
3. **Excluded:** `restricted`, quoting and linking the clause; refused whatever `license` says, as is `license = "unknown"`.
4. **Undecided:** `undecided`, naming the decision and linking the terms; refused, `none` included, until a tier replaces it.

`routes check` refuses anything else. Production models need `author`, `source` and `credit` for the credits page, which marks `credit_required` models as licence-required credits, links SPDX ids to spdx.org and `LicenseRef-` ids to their `terms` URL. Tier moves are the maintainer's: 2026-10-10 cleared `CC-BY-NC-4.0`, `CC-BY-SA-4.0` and `LicenseRef-Datalab-OpenRAIL-M` (this project's id for Datalab's differing modified Open RAIL-M terms on Surya 2, Marker and Chandra) because the site is entirely non-commercial; 2026-10-11 added tier 2 (use whichever engine reads better, and credit it; explicit restrictions still exclude); 2026-11-03 ([#1479](https://github.com/tgoodyear/usnewsmap.com/issues/1479)) added `CC-BY-NC-SA-4.0` (Yiddish OCR Corpus models, `credit_required`) and `AGPL-3.0-only` (Jochre 3). No production route to a `credit_required` or tier 2 model may merge without a credits page naming each production engine and model with author or publisher, source, and licence or "no explicit licence".

### 13.7.4 routes.toml

The committed file has one route, `minimal` (`match = {}`, Tesseract `auto`). The design, with full matching:

```toml
schema = 1
version = 1                      # raise on every change; CI refuses a change without it

[scripts]                        # title-level facts by LCCN, once a typeface is checked (#246)
# "<lccn>" = "Latf"

[[route]]
id = "german-pre1920"
match = { language = ["deu"], date_to = "1919-12-31" }
candidates = [                   # a candidate's options override the profile's defaults
  { engine = "tesseract-5.5", profile = "deu_latf+deu" },
  { engine = "tesseract-5.5", profile = "deu" },
]
fallback_after = 2               # receives per candidate before the next; 2 if absent, at least 1
timeout_secs = 1200

[[route]]
id = "worst-english-batches"     # base batch names, without _verNN
match = { language = ["eng"], batch = ["nn_kant", "txdn_japan", "nn_bentham", "nn_carson", "kyu_frenchie"] }
candidates = [{ engine = "tesseract-5.5", profile = "eng" }]

[[route]]
id = "serbian"
match = { language = ["srp"] }
candidates = [{ engine = "tesseract-5.5", profile = "srp+srp_latn" }]

[[route]]
id = "default"
match = {}
candidates = [{ engine = "tesseract-5.5", profile = "auto" }]
```

### 13.7.5 Matching

- **Inputs:** the message (`language`, `batch`, `reason`, `score`; format unchanged), the `PageKey` (LCCN, date, edition, sequence) and `[scripts]`.
- **Keys:** `language` (ISO 639-3), `script` (ISO 15924, from `[scripts]`), `lccn`, `batch` (base name without `_verNN`, as in curated rows, the release and messages, 12 Step 2; exact or `prefix*`), `date_from`, `date_to`, `reason` (`user` or `bulk`), `score_min`, `score_max` (damage before OCR).
- All keys must hold; a list matches any value; a key the page lacks never matches. First match in file order wins; the last route matches everything. New keys change only `usnm-ocr-route`.
- **Language codes.** 13 catalog MARC codes differ from ISO 639-3 (`ger`, `fre`, `cze`, `slo`, `dut`, `chi`, `gre`, `rum`, `arm`, `wel`, `ice`, `baq`, `alb`; `crates/usnm-core/src/names.rs`), and the catalog may hold LoC's lower-cased name where `language_code` has none (`pennsylvania german`). `usnm_core::lang` (12 Step 4) maps both (`ger` to `deu`, `pennsylvania german` to `pdc`) for the seeder and survey; unmapped titles are logged and not queued. Validation (12 Step 7) accepts only known ISO 639-3 codes, so `ger` is dead-lettered as `language` at once rather than failing `no_model` every receive.

### 13.7.6 Choosing a candidate

A candidate is usable when its engine is allowed on the node, its breaker is closed, its image is pulled, its profile covers the language (`auto`: the first profile that does), and in production it passes the licence gate.

Not built beyond the first usable profile (§13.7). As designed, routes need at least one candidate and `fallback_after` ≥ 1 (default 2); `routes check` and the loader reject violations. The worker starts at candidate `min((dequeue_count - 1) / fallback_after, n - 1)` (integer division, from 0) and takes the first usable one from there, so two failures on the first candidate move the third receive to the second, whatever the cause, with no shared state between nodes (which can't update messages, ADR-0015). `unsupported` and `bad_input` advance within the receive. With nothing usable: transient `no_route_here`. Runs records keep `candidate_rank`.

**Receive guard (history, never built).** Azure Storage queues let a node hide a message only at receive time and can't requeue it, so a worker receiving through an engine outage would use up every visible message's 5 receives within hours. The design guarded receives: no receive while no allowed engine was usable (backoff 1 s doubling to 60 s); a node-wide backoff after `no_route_here` or `no_model` (60 s doubling to 15 minutes); and, with some engines down, peek-then-defer receives (at most 10 a minute, 1,800 s visibility) that left blocked messages hidden so routable ones reached the front, moving a message blocked twice to `ocr-deadletter` with cause `unroutable` for the seeder to requeue. That seeder side is built (`crates/usnm-ocr-local/src/seed.rs`, 12 Step 10): `unroutable` pages are requeued outside the 3-attempt (`MAX_REQUEUES`) limit for `dequeue_count` dead letters, after 6 hours doubling per cycle up to 48, and a requeued message starts at dequeue count 0. Engines a node can never run were to get capability queues (`ocr-bulk-gpu`), which is why `routes check` was to require one route's candidates to share a capability group. On BOINC, plan classes keep pages off hosts that can't run their engine: the scheduler sends work only to hosts whose plan class fits, and the claim takes only pages an installed model covers ([queue-fed work](../boinc/server/batch-scheduler.md#queue-fed-work)).

### 13.7.7 Cascade (optional, per route)

```toml
[route.cascade]                  # belongs to the [[route]] above it
when_damage_above = 0.25         # the first engine's damage after OCR
then = { engine = "kraken-7.1", profile = "pp-ocrv6-medium" }
keep = "min_damage"
min_top_word_hits = 30           # below this, damage is noise: keep the first reading
min_chars_ratio = 0.8            # much less text can look less damaged: keep the first
require_granularity = "line"     # the second reading needs real line geometry
min_word_overlap = 0.6           # share of the first reading's dictionary words that reappear in the same blocks
```

- The second engine reads the same image through the same ALTO writer and normalization. Only the kept reading goes to `ocr-out`; both runs records are written (`selected` true or false), and `ocr_engine` gains `select=cascade:min_damage`.
- The guards exist because the damage metric rates fluent invented text as good: CHURRO found major hallucinations in 36% of 50 zero-shot Qwen2.5-VL-3B predictions, and a 2026 study of Uruguayan microfilm found vision-language models normalizing spelling, adding content and swapping names behind low median error rates.
- Not built. Enabled only after `usnm-ocr-survey replay` shows a worthwhile gain above the threshold from existing runs; never selects between vision-language models by damage alone. `routes check` rejects `score_*` keys and cascades on routes matching `jpn` or `und`, where `damage_after` is null (§13.4.7).

### 13.7.8 Validation, tools and distribution

- **Built.** `usnm-ocr-worker routes check [--engines <file>] [--routes ocr/routing/routes.toml] [--lock ocr/engines/profiles.lock] [--update-lock]` refuses a production candidate (or cascade target) whose code or models fail the licence gate (§13.7.2: `license` neither listed nor `none`, a `none` entry missing `source`, `author`, `fetched`, `note` or `credit`, any `restricted` or `undecided`, or missing `author`, `source`, `credit`), and a profile whose digest differs from `profiles.lock` or a pinned profile with no entry. `auto` checks every profile of the engine. CI runs it.
- **Designed, not built.** Also failing on an unknown engine or profile; empty `candidates` or `fallback_after = 0`; one route's candidates in different capability queues; options outside `tunable`; an unreachable route or no catch-all; a `batch` pattern ending in `_verNN`; `score_*` or a cascade on `jpn` or `und`; timeouts over the budget; a changed file without a new `version`; and `--survey-results`, warning when a production route's locked digests have no survey result. `routes explain --page <key> --language <code> --batch <batch>` to print the route and dropped candidates, and `routes diff --from-version <n> --to-version <n> --manifest <sample.jsonl>` to count pages whose engine or profile changes. `routes.golden.toml` with a default-route page checking its resolved profile, merged options and `image.dpi` 300.
- **Distribution.** The worker embeds the catalog; `--engines` replaces it. Publishing the bundle as an OCI artifact was planned, not built.
- Rows record route and routing version; runs records and ALTO add the bundle digest. Written rows don't change; re-reading under a new route means requeueing.

## 13.8 Provenance

### 13.8.1 ocr_source and ocr_engine

`ocr_source` is `usnm-<family>` (`usnm-tesseract`; later `usnm-kraken` or `usnm-doctr`; the Japanese job's `usnm-ndlocr-lite` already fits). `ocr_engine` is a tag `usnm-core` formats and parses (`OcrEngineTag`):

```text
<family>/<engine version> profile=<profile> image=sha256:<12 hex> models=sha256:<12 hex> route=<route id>@r<N> contract=<n>[ select=cascade:min_damage]
tesseract/5.5.0 profile=deu_latf+deu image=sha256:3f9a0c1d2e4b models=sha256:8c2d71aa09fe route=german-pre1920@r1 contract=1
```

- Family, engine id, profile id and route id match `[a-z0-9][a-z0-9_.+-]{0,63}`; engine versions `[0-9A-Za-z][0-9A-Za-z.+-]{0,63}`; which exclude space, `=`, `/` and `@`, so tags parse back into their fields. The loaders, `routes check` and the hello check enforce it, `OcrEngineTag` won't format anything else, and a test round-trips every lock entry and route.
- `image` is the manifest digest that ran (adapter, engine, models); `models` is the sha256 of the profile's sorted `<name> <sha256>` lines (example digests made up). Short digests resolve through the runs record and `engines.lock.json`'s git history. An unpinned local image writes `image=local`, refused by the worker in production and by `ocr-sync` (12 Step 8).
- The short key, `<family>/<engine version> <profile>` (`tesseract/5.5.0 deu_latf+deu`), is used by the release's engine index (`ocr_local_pages.bin`, 12 Step 9) and the API's `ocr.engine`, so they don't grow per routing version; rows and runs records keep the full tag. One model set per profile id (§13.7.2) means a short key always names one model set.
- Rows written as of 10 November 2026 carry `route=minimal@r1` (`usnm_ocr_worker::engine::ROUTE` and `ROUTE_VERSION`), the one route in `routes.toml`; live short keys are `tesseract/5.5.0 <profile>`.
- The parser also accepts the older `tesseract-<version>/<models>` and `ndlocr-lite <commit>` forms; the API passes the string through.

### 13.8.2 Stored ALTO

- ALTO 3.1 (namespace `http://www.loc.gov/standards/alto/ns-v3#`, schemaLocation `alto-3-1.xsd`), as `ocr/ja-ocr/alto.py` writes; CI validates golden pages with `xmllint --schema`.
- `MeasurementUnit` `pixel` in the frame of the fetched IIIF full image (`<service>/full/full/0/default.jpg`), whose size is the page `WIDTH` and `HEIGHT`; pixels need no dpi, while inch1200 would need LoC's ALTO per page. `usnm-alto` converts to inch1200 when a dpi is known. `sourceImageInformation/fileName` is the URL of the file read: the IIIF URL, or the batch JP2's storage-service URL, which has the same pixel size (12 §12.2.4).
- Geometry only at the reading's granularity; finer elements inherit the parent box and are never used as word positions (the survey's CER reads the granularity first, §13.9).
- TextBlock `LANG` is the page's ISO 639-3 code or the block's `lang`; engine ALTO LANG is ignored (NDNP Open OCR writes `eng` everywhere).
- The description carries provenance (registry, digests and commit made up). `input_sha256` is kept because LoC can re-encode IIIF derivatives.

### 13.8.3 Runs record

`runs/<lccn>_<date>_ed-<n>.<run_id>.parquet`, create-only, Parquet metadata `usnm.runs.schema=1`, written after the ALTO and before the part, so only for receives that write a page. One row per read in the receive: the kept read (`selected` true), a cascade's other read, and earlier candidates answering `unsupported` or `bad_input` (`status`, `error_kind` set). `usnm-ingest ocr-sync` picks it up with the part (12 Step 8; otherwise the 30-day `ocr-out` lifecycle deletes it), checks it with `usnm-ocr-contract`'s strict reader and writes `curated/ocr-local/runs/`, adding `ocred_at` (the part blob's server creation time, as for the overlay row); the node writes only `node_finished_at`. 12 Step 8 check 7 requires the selected row's `ocr_engine` to equal the part's and refuses `image=local`. The survey writes the same `RunRecord` as JSON lines (`"schema": 1`) for every read, failed or not.

| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Identity      | `run_id`, `doc_id`, `node`, `worker_version`, `contract`, `ocr_engine` (the full tag of §13.8.1, the same string as the overlay row's for the kept read)                 |
| Engine        | `engine_id`, `family`, `engine_version`, `adapter`                                                                                                                       |
| Artifacts     | `image_ref`, `image_digest`, `models_digest`, `models_json`                                                                                                              |
| Configuration | `profile`, `options_json` (defaults merged with the route's options), `scale`, `tiles`                                                                                   |
| Routing       | `route_id`, `routing_version`, `routing_digest`, `candidate_rank`, `selection`, `selected`                                                                               |
| Outcome       | `status`, `error_kind`                                                                                                                                                   |
| Resources     | `seconds_wall`, `seconds_cpu`, `peak_mem_mb`, `instance_peak_mem_mb`, `oom`, `instance_restarts`, `model_load_seconds` (start to `hello`), `models_loaded`, `cold_start` |
| Input         | `image_sha256`, `image_width`, `image_height`, `dpi`, `dpi_source`                                                                                                       |
| Layout        | `granularity`, `reading_order`, `markup`, `blocks`, `lines`, `words`, `mean_conf`, `text_chars`, `text_sha256`, `engine_stats_json` (the adapter's `engine_stats`)       |
| Damage        | `damage_before` (the message's `score`, which main drops), `damage_after` (null for `jpn` and `und`)                                                                     |

BOINC's `collect` writes no runs record (12 §12.2.2), so pages read on BOINC have none. Built in #307 (§13.11 step 8) for the retired worker: `provenance::mint_run_id` (strictly increasing per process) mints the `run_id` before the engine call, and the kept read is the only row (`selected`, `selection` `route`, rank 0); `unsupported` candidates and a cascade's other read come with routing (§13.7, #371). Until routes exist (#371), `routing_digest` is null, `options_json` holds the worker's own options (`dpi`, `psm`), and stored ALTO settings carry `image`, `models`, `profile`, `options`, `route`, `routing=r<N>` (no digest yet), `contract`, `adapter`, `run_id`, `input_sha256` and `damage_before`, after the full `ocr_engine` tag. Direct Tesseract reports its Podman image as `image_ref` (`local` for a host binary) with models from `ocr/engines/tesseract/models.lock`; contract engines report hello's adapter, models and `models_loaded`, the result's `markup` and `engine_stats`, and `model_load_seconds` when cold. `cold_start` is true when the instance hasn't read a page yet, new or idle. `seconds_cpu`, memory and `script` are null, `dpi_source` is `assumed`, `damage_after` is forced-language.

- **Reads that write nothing** (the retired worker, `crates/usnm-ocr-worker`). A timeout, crash, OOM, `convert` failure or abandoned page writes no ALTO, runs record or part; instead one `ocr_engine_run` warning (target `ocr_engine_run`, in the page's span, so it reaches Application Insights) carries the Identity, Engine, Routing, Outcome and Resources fields and no page text, with `status` `failed`, `timeout`, `bad_input` or `abandoned` and `error_kind` a §13.4.6 kind, `budget`, `abandoned` / `shutdown`, or `too_large`. `ocr.engine_errors` and `ocr.pages_failed` count them as before. Once the page's runs record is uploaded, a later failure sends no event. Direct Tesseract output breaking §13.4.7 step 1 is `engine_protocol`; a file it didn't write stays `engine`. `seconds_cpu`, memory, contract-engine OOM kills and `instance_restarts` aren't reported.

### 13.8.4 What stays the same

- The overlay's 16 columns, so `ja-ocr`'s Python writer and `usnm_overlay::read_part` don't change.
- `loc_text` on worker rows stays the queue reason (`bulk`, `user`); the `curated/ocr-local/` reader (12 Step 9) must not use `ocr_ja::load` or `ocr_ja::indexable`, which read it as LoC's failure class.
- Output names `alto/<doc_id>.<node>.<stamp>.xml` and `pages/<lccn>_<date>_ed-<n>.<node>.<stamp>.parquet`, with `<node>.<stamp>` now the `run_id`.

### 13.8.5 Reproducibility

- Base images pinned by digest; Debian packages from `snapshot.debian.org` at a fixed timestamp, or the engine built from a sha256-pinned tarball (version pins against the live mirror can't rebuild). The Tesseract engine and BOINC worker images take their snapshot packages from apt bases built once and pinned by digest in `ocr/engines/tesseract/base.lock`, so a build doesn't depend on the mirror being up (#1681).
- Python: `pip --require-hashes` from a transitive lock (`pip-compile --generate-hashes`) seeded from the survey images' `pip freeze`.
- Models pinned by sha256 in `models.lock`, checked at fetch and build, re-hashed at every adapter start, tied to the lock by the hello check. Mutable sources (the Dropbox archive American Stories and NDNP Open OCR use) were to be mirrored as sha256-keyed OCI artifacts (not built).
- Planned: `deterministic` engines get a CI golden test (three fixture pages, stored-text sha256 per image digest), and `usnm-ocr-survey repro --engine <id> --pages 20` reads pages twice and compares hashes; torch on CPU and llama.cpp across thread counts may differ.
- Engine and worker images are pushed by digest to public GHCR packages ([worker image](../boinc/apps/worker-image.md)).
- Planned, not built: when a `routes.toml` version merges, the lock-publishing job sets no-delete and no-write on every digest a production route names, and `engines gc` and registry cleanup skip them. CI can't see production rows (exchange account firewall, private curated data), so the lock follows routes that can write rows. Rebuilds never reproduce a digest.

- Not built. Round 1 ran on a Python harness ([report](../reports/2026-10-ocr-engine-survey/report.md)), and engine comparisons since then use the OCR bench ([bench](../ocr/bench.md)). The `usnm-ocr-survey` crate on `main` scores gold sets and builds the gold bundle and bench (`score`, `bundle-build`, `bench-*`, `qwen-bench-*`) for `usnm_gold` and `usnm_qwen`; it has none of the commands below. The node pull and `usnm-ocr-worker run` boxes are history (#966), and images go to GHCR, not a private registry.
- As designed, `usnm-ocr-survey` is a second binary in the worker crate, using the same engine host, podman settings, limits, lock, profiles, tiling, ALTO writer, `normalize_ocr` and `usnm_core::damage`. It adds only a plan, survey-only engines and profiles, and partial output on timeouts. A result is keyed by engine id, image digest, models digest, profile and options, which is what a production route resolves to.
- **Commands** (named flags only):
  - `usnm-ocr-survey run --sample <dir> --work <dir> --plan ocr/survey/plan.toml --engines-lock ocr/engines/engines.lock.json [--engines tesseract-5.5] [--parallel 1] [--pages-per-group 5]` writes canonical ALTO, normalized text and `RunRecord` lines, skipping jobs that have a record. A plan run may be `{ route = "production" }` to route each page as production would.
  - `usnm-ocr-survey throughput --engine tesseract-5.5 --profile deu_latf+deu --instances 3 --pages 8` reports pages per day for a pool size.
  - `usnm-ocr-survey score --work <dir> --manifest <file> --truth <crops dir>` reports damage after OCR (none for Japanese, scored by crop CER only), CER on hand-transcribed crops, ALTO validity of the engine's own output, and partial and timeout counts, as CSV and Markdown. CER follows the run's granularity: for `word` and `line`, the compared text is the contiguous page-text span from the first to the last String whose centre is in the crop, so text the reading order pulled in from other columns counts as errors; for `block` and `page`, the transcription is aligned against the text of blocks overlapping the crop (best local alignment, edit distance over the span), in its own column `cer_block_aligned`.
  - `usnm-ocr-survey replay --work <dir> --cascade-threshold 0.25` computes best-of and cascade gains from existing runs with no new OCR.
  - `usnm-ocr-survey repro` (§13.8.5).
- **Plan file.** `ocr/survey/plan.toml` replaces the `PLAN` table in the survey's `run.py`. Its runs are `{ engine, profile, options, scale }` like route candidates (`scale` beside `options`), so a winner copies into `routes.toml` unchanged. Profile defaults apply, and every run gets the `image.dpi` the worker would send (300 at scale 1).
- Over the Python survey it keys pages by `doc_id`, uses ISO 639-3, scores the text the overlay would store, and measures resources from the cgroup; partial output stays out of the `ok` counts.
- **Round 1** (Python) results are indicative only. Its images were saved with `podman save` by image id on 12 October, before node 1 was deleted: seven archives kept outside the repository (five `ocr-survey/<engine>` images, an untagged Tesseract build, the llama.cpp image) with `podman image inspect` output, a checked `SHA256SUMS` and both nodes' image lists; restore with `podman load` and `podman tag <id> ocr-survey/<engine>`. Survey Containerfiles move to `ocr/engines/<family>/` with adapter entrypoints (new digests), and the Tesseract arm is re-run on the production image before any routing decision; the other engines are re-run as they get adapters.

## 13.10 Adding a new engine

NDLOCR-Lite reached production without steps 8 to 10: a catalog entry with `production = true`, a pinned image with a contract adapter, its own BOINC app (`usnm_ndlocr`) and a route in code (§13.7) ([NDLOCR-Lite on BOINC](../boinc/apps/ndlocr-lite.md), [releasing an app version](../boinc/apps/app-release.md)). The full list, as designed:

1. **Catalog:** a §13.12 row from fact-checked sources (code and model licences, outputs, ALTO, hardware, fit; unconfirmed items in Unconfirmed).
2. **Licences:** each model in `engines.toml` with its tier (§13.7.2), terms quoted and linked; `undecided` for ambiguous terms, survey only until the maintainer decides.
3. **Image:** `ocr/engines/<family>/Containerfile`, base by digest, packages pinned (§13.8.5), models from `models.lock` by sha256, `USER 10001`, offline caches, nothing fetched at run time.
4. **Adapter:** a Rust binary in `usnm-ocr-adapter` (CLI, HTTP, script per page) or a `usnm_ocr_adapter` module importing a Python library once; ALTO if the engine has it, else `boxes.json` with units, reading order and markup; regular files in `/out/<run_id>/` only; never tiles; logs to stderr.
5. **hello:** every model file with sha256, profiles with ISO 639-3 languages and tunables, `cancel`, `models_loaded`.
6. **Conformance** locally and in CI (§13.4.8).
7. **engines.toml entry:** measured limits, timeouts within the budget, `max_instances`, profile `defaults` and `tile`, production flag.
8. **CI** builds, pushes and opens the lock PR.
9. **Survey:** plan runs, scores, and `replay` for a cascade candidate.
10. **Route** only with survey results for the exact digests: `routes check --survey-results` passes, `routes.golden.toml` updated, `version` raised.
11. **Docs:** update the §13.12 row.

### OCR credits page (#372)

`/credits` reads per-engine page counts from `/v1/status` (`published.sources.ocr_local.by_engine`, `published.sources.ocr_ja.by_engine`), frozen in the serving release. `ocr_ja.by_engine` unions Japanese-index pages and main-index Latin-script replacements, deduplicated per page and engine, excluding hidden main-index copies; a reading the Japanese index serves on its own keeps its credit. Older releases fall back to `ja_latin.by_engine` when available. Each "Our OCR" badge links to its engine key's fragment; the footer and "Pages we read ourselves" link to the page.

Vite parses `ocr/engines/engines.toml` at build time for the page and its tests, showing only serving engines and their selected profiles' models; NDLOCR-Lite, which predates the catalog, uses its catalog credit and bundled DINOv3 model. Survey presence isn't evidence of use. An unknown serving key or incomplete credit is an error, and the end-to-end inventory coverage test fails rather than omitting the engine. Licence links, mandatory attribution and tier evidence come from the catalog. Model revisions the serving inventory doesn't record are labelled unrecorded; current worker image pins are checked against the catalog but don't prove which revision produced a reading under a short key, so those stay unrecorded until per-reading digests can verify them.

Each release freezes its catalog entries and the mandatory-attribution list in `credits.json` (checked by the reference manifest, exposed as `published.sources.ocr_credits`); publication fails if a serving key can't be credited. The page prefers that snapshot, so later catalog edits don't change a version's credits; only older releases use the catalog bundled at web build time.
