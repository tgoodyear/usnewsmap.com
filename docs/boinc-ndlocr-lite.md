# Japanese OCR with NDLOCR-Lite

Issue [#626](https://github.com/tgoodyear/usnewsmap.com/issues/626) adds a CPU-only
volunteer engine for Japanese scans. It uses the same upstream revision and
conversion as `Dockerfile.ja-ocr` and `ja-ocr/jaocr.py`, without the Flet desktop UI.
Engine-level routing is tracked in [#624](https://github.com/tgoodyear/usnewsmap.com/issues/624).

## Pinned engine and contract

Build from the repository root:

```sh
docker build -f ocr/engines/ndlocr-lite/Containerfile -t usnm-ndlocr-lite .
python3 scripts/boinc/smoke-ndlocr.py usnm-ndlocr-lite "$PWD/ndlocr-smoke"
```

The Python and Rust bases are pinned by digest. `NDLOCR_COMMIT` is
`636d1cfeb1331f89f4048f416e49e23a09a714b5`, matching the existing Japanese job.
The upstream source archive has a SHA-256 check, and
`ocr/engines/ndlocr-lite/models.lock` independently pins all four ONNX models
(DEIM layout and the 30-, 50-, and 100-character PARSeq recognizers). The build
checks each model's bytes; the Rust adapter hashes and checks them again before
sending `hello`. Model loading happens per page, and counts toward its deadline.
The Japanese character set and layout configuration come from the checked source
archive, not a mutable URL or a runtime download.

The image keeps National Diet Library's CC-BY-4.0 licence, the layout model's
additional DINOv3 licence (already cleared by the maintainer), and attribution
`NOTICE` beside the models at `/opt/ndlocr-lite/src/model/`. Upstream dependency
notices are retained too. Production model names and credits are in
`ocr/engines/engines.toml`; the survey-only entry remains separate so historical
Japanese credit snapshots are not silently relabelled.

`usnm-ocr-adapter-ndlocr-lite --contract 1 --threads 1` speaks
`usnm-ocr-engine/1` (ADR-0016), with family/id `ndlocr-lite`, profile `default`,
language `jpn`, and line granularity. Its root filesystem can be read-only, with
no network or capabilities. Mount inputs at `/in` (read-only) and output/scratch
at `/out` (writable). The adapter invokes the unmodified upstream CPU CLI for one
image and kills/reaps its process group if the deadline expires. It requires
both XML and text even when upstream exits successfully; upstream can exit 0
without processing an image. Extensionless BOINC scans get a detected JPEG,
PNG, or JP2 suffix in private job scratch.

The adapter converts NDLOCR XML to the **same ALTO 3.1 in inch1200** as
`ja-ocr/alto.py`: fractional reading order, one String per line, block unions,
confidence clamping, scan dpi, and optional LoC page-size clamping. It returns
the upstream text with `jaocr.normalize`'s NFC/control-character/whitespace
rules, not the general pipeline's Latin ligature expansion or dehyphenation.
The on-prem contract worker may still derive and store its standard pixel ALTO
and text, as ADR-0016 requires. The small Rust golden fixture was generated by
the existing Python converter; the image smoke test reads the real Japanese
headline fixture twice and compares both the converted ALTO and normalized text
against the existing Python job.

## Reproducibility and resources

`hello.deterministic` is deliberately false: matching model hashes do not prove
bit-identical ONNX floating-point output between x86 and ARM hosts. The smoke
test checks two same-host readings, **not** cross-host determinism. The pilot
must retain each host's text and compare readings before relaxing exact-result
validation. Japanese similarity must use characters or character n-grams, not
whitespace-delimited word bags (a Japanese line may be one token).

The development machine has a Docker CLI but no running daemon. A local image
build and representative per-page CPU time/peak memory have **not** been
measured. The image CI reports wall time, CPU seconds and peak RSS for the small
headline fixture, including model loading; that is a smoke cost, not a newspaper
page estimate. Do not derive production scheduler bounds from it. Before a
broad campaign, measure several full-size pages on a volunteer host, record CPU
model/architecture and CPU quota, repeat on another architecture, and set
`rsc_fpops_est` from CPU seconds times that host's measured FLOPS and
`rsc_memory_bound` above its observed peak with headroom.

## Operations after merge

1. Publish the reviewed engine/worker image by digest and sign/publish the BOINC
   app version. The engine workflow supports main-only manual publication:

   ```sh
   gh workflow run boinc-ndlocr-lite.yml --ref main -f correlation=ndlocr-pilot
   ```

2. Stage a small Japanese pilot on pages the cloud job has not already read.
   Keep the LoC failure class (`missing`, `empty`, `short`, `garbled`, or `mixed`),
   image URL and geometry; `bulk` is a queue reason, not a Japanese failure class.
3. Compare ALTO/text with `jaocr.py` on the same images and record per-page cost
   and cross-host similarity before increasing the sample.
4. Collect only verified readings into the curated `ocr-ja/` overlay read by the
   release, with `ocr_source = usnm-ndlocr-lite`. Preserve the filtering in
   `crates/usnm-ingest/src/ocr_ja.rs`, including the Japanese-character bar for
   mixed pages and the English-column safeguards. Publish ALTO before its part;
   retries must not overwrite a different reading.
