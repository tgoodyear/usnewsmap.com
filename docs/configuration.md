# Configuration

The API (`usnm-api`) is configured with environment variables. Defaults suit local development against the synthetic fixtures; production sets them in Bicep (`infra/modules/containerapp.bicep`).

| Variable                                                  | Default                                         | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `USNM_BIND`                                               | `0.0.0.0:8080`                                  | Listen address                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `USNM_BACKEND`                                            | `memory`                                        | `memory` (JSONL indexes under `USNM_DATA_DIR/indexes`) or `quickwit`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `USNM_QUICKWIT_URL`                                       | `http://127.0.0.1:7280`                         | Quickwit base URL (in production the localhost sidecar, or `http://usnm-search-ca-<env>` with the searcher app, #267)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `USNM_SEARCHER_METRICS_SECS`                              | `60`                                            | With the Quickwit backend, how often the API reads the searcher's cache, thread pool and runtime metrics from `USNM_QUICKWIT_URL/metrics` and reports them as `api.searcher_cache_*`, `api.searcher_pool_tasks` and `api.searcher_runtime_*` (08 §8.1.2); `0` turns it off, and with it the API's only way to see that the searcher restarted, so a restarted searcher is no longer warmed (06 §6.5)                                                                                                                                                                                                                                                                                                                                                                                                    |
| `USNM_DATA_DIR`                                           | `fixtures/data`                                 | Local data directory: the memory backend's `indexes/`, and the default reference location                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `USNM_REFERENCE_URL`                                      | `USNM_DATA_DIR`                                 | Where `current.json` and the reference snapshots live: a Blob container URL (`https://{account}.blob.core.windows.net/reference`) or a local directory. Every file is checked against the snapshot's `manifest.json`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `USNM_RESPONSE_CACHE_URL`                                 | unset                                           | Persistent response cache (`https://{account}.blob.core.windows.net/cache` or a directory). Entries are `{index_version}/f{format}/{sha256}.json.zst`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `USNM_PERSIST_AFTER_MS`                                   | `500`                                           | Only responses that took at least this long to compute are persisted                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `USNM_ALLOWED_ORIGINS`                                    | `https://usnewsmap.com`                         | Comma-separated CORS origins (GET only)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `USNM_SITE_HOST`                                          | `usnewsmap.com`                                 | The site's hostname. Requests for `www.` plus this name get a 301 to `https://` plus this name, with the same path and query                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `USNM_SEARCH_TIMEOUT_SECS`                                | `10`                                            | How long a visitor's request waits for a response (plus 2 s with a persistent cache); past it the API answers `202 Accepted` and the search carries on (06 §6.3.5)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `USNM_COMPUTE_CAP_SECS`                                   | `120`                                           | Limit on one search computation and each backend call in it, from when it gets its slot; past it the search fails with a `503` timeout, which is not cached. A search still queued for a slot after this long gets `503 /errors/busy`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `USNM_COMPUTE_CONCURRENCY`                                | `2`                                             | Per-replica searches computed at once outside provisioned shared-searcher mode; provision treats this as the searcher-wide visitor budget and divides by `USNM_API_MAX_REPLICAS` (default 2), rounding down, with a minimum positive share required (#364). Sidecars keep the full per-replica budget. Settings require provision. Searches computed at once (on a 2-vCPU searcher more added no throughput, 06 §6.5; #251 re-measures it at 3.75 vCPU), including those still running after a `202`; when all are busy, a new search queues for one (06 §6.6)                                                                                                                                                                                                                                          |
| `USNM_SEARCH_QUEUE`                                       | `16`                                            | Searches allowed to wait for a slot, first come, first served; each keeps its place while its visitor keeps asking, and its `202` says how many are ahead. A search that finds the queue full gets `503 /errors/busy` at once                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `USNM_ABANDON_AFTER_SECS`                                 | `15`                                            | A computation no request has waited on for this long is cancelled (the visitor changed the search or left); at least 5                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `USNM_REFRESH_SECS`                                       | `600`                                           | How often `current.json` is re-read for a newly published version                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `USNM_PREWARM_QUERY_SECS`                                 | `60`                                            | Cache warm-up before a version serves: limit on each query                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `USNM_PREWARM_BUDGET_SECS`                                | `900`                                           | Cache warm-up before a publish swaps a version in: limit on the whole run; the rest is skipped                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `USNM_PREWARM_STARTUP_BUDGET_SECS`                        | `300`                                           | The same limit for the warm-up after a start. By default the replica isn't ready until it ends, so in a rollout the old revision serves meanwhile                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `USNM_PREWARM_TOP_SEARCHES`                               | `20`                                            | Cache warm-up: after the examples, this many of the most frequent searches in the search log; the examples searched most go first (`0` turns both off)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `USNM_PREWARM_LOG_DAYS`                                   | `28`                                            | Cache warm-up: how many days of the search log are counted, back from yesterday                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `USNM_READY_CAP_SECS`                                     | `USNM_PREWARM_STARTUP_BUDGET_SECS` + 60 (`360`) | After a start, `/readyz` reports ready once the warm-up ends or this much time passes; past it the replica serves while the warm-up finishes. The default lets a rollout move traffic only to a warm replica (06 §6.6). At most 86400 when set, like the warm-up budgets. `infra/modules/containerapp.bicep` sets it and `USNM_PREWARM_STARTUP_BUDGET_SECS` from one budget, so the startup probe covers the cap: the budget plus 60 s, or `60` where the app scales to zero (a replica starting from zero has no other one serving, and the visitor who woke it waits for it)                                                                                                                                                                                                                          |
| `USNM_CACHE_MB`                                           | `256`                                           | In-process response cache size                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `USNM_RATE_PER_MIN`                                       | `120`                                           | Per-client token bucket refill rate on `/v1` (`0` disables)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `USNM_RATE_BURST`                                         | `40`                                            | Per-client bucket size                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `USNM_TRUSTED_PROXY_HOPS`                                 | `1`                                             | Proxies that append to `X-Forwarded-For` (1 = Container Apps ingress, 2 = a proxy such as Front Door + ingress, 0 = use the peer address)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `USNM_TRUST_CF_CONNECTING_IP`                             | `false`                                         | `true`: the client address (for the rate limit and page views' location) comes from Cloudflare's `CF-Connecting-IP` instead of `X-Forwarded-For`, and only on requests whose peer is loopback, as behind a cloudflared and proxy on the same host. A request from any other peer, or without the header, counts its peer's address. `USNM_TRUSTED_PROXY_HOPS` is then ignored. Off on Container Apps, whose ingress is the peer                                                                                                                                                                                                                                                                                                                                                                         |
| `USNM_BACKEND_CONCURRENCY`                                | `8`                                             | Backend queries allowed at once; waiting for a free one counts against the computation limit                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `USNM_AMERICAN_STORIES_SEARCH`                            | `true`                                          | `false` searches LoC's text alone on a version built with American Stories' text, as if `current.json` had no `american_stories`: no `text_as` fields, no `matched_in` or `snippet_source`, no `total.american_stories_only`, and `/v1/meta` says `"american_stories": false` (05 §5.5.4). Search responses computed with it off are cached under keys of their own (`…\|american_stories=off`), so neither state serves the other's; with it on the keys are unchanged, and Japanese queries keep theirs either way. It has no effect on a version that searches both texts in one field (`text_layout: 2`, 05 §5.5.7): the API logs a warning and searches both. Production sets it from the deployment setting of the same name ([operations](operations/american-stories.md#american-stories-text)) |
| `USNM_CONGRESS_SEARCH`                                    | `true`                                          | `false` turns Congress search off on a version that has a Congress index set (#229): the Congress indexes aren't loaded or prepared, `source=congress` answers 422 before any cache is read, and `/v1/meta` says `"congress": null`, without a rebuild or touching `current.json`. With it on, a Congress set that fails to load or prepare is dropped with a warning and the newspapers still serve (06 §6.3.10). Production sets it from the deployment setting of the same name; browsers may keep a Congress response for up to a day (06 §6.5)                                                                                                                                                                                                                                                     |
| `USNM_PAGE_LANGUAGE_FILTER`                               | `smaller`                                       | On a version with page languages (05 §5.5.8), how `lang=` is rendered: `smaller`, the side with fewer pages (`page_language:IN [L]`, or the complement `NOT page_language_set:IN [...]`); `match`, the match side always. Both find the same pages, so cached responses serve either way; the setting is for measuring one against the other (#289). Production sets it from the deployment setting of the same name (Bicep `pageLanguageFilter`; empty leaves it unset)                                                                                                                                                                                                                                                                                                                                |
| `USNM_BROWSE_PAGES`                                       | `false`                                         | `true` lets `/v1/hits` list one newspaper's pages without a search word (#274, 06 §6.3.4): `lccn` (exactly one) and no `q`, by date, each page with the opening of its text as its snippet. `/v1/meta` reports it as `browse_pages`, and the site offers "Browse pages" in the newspaper filter only then. Off by default: a list with no word has no posting list to skip splits by, so it reads every split of the version for the title's pages, and is measured on the full index before it is turned on. Production sets it from the deployment setting of the same name (Bicep `browsePages`; only `true` sets it)                                                                                                                                                                                |
| `USNM_FIXTURE_SLOW_TERM`, `USNM_FIXTURE_SLOW_MS`          | unset, `5000`                                   | End-to-end tests only, memory backend only: an aggregate search whose query contains the term waits this many milliseconds first, to stand in for a cold search                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `IDENTITY_ENDPOINT`, `IDENTITY_HEADER`, `AZURE_CLIENT_ID` | set by Container Apps                           | Managed identity for Blob; `AZURE_CLIENT_ID` selects the user-assigned identity. Without them, the Azure CLI login is used (`az login`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `RUST_LOG`                                                | `info`                                          | Log filter (logs are JSON and never include query strings)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Related settings

- **Web app build-time variables** (`VITE_*`, the dev server's API origin): [`web/README.md`](../web/README.md).
- **Ingest pipeline** (`usnm-ingest`): the store, state and index-target options also read environment variables (`USNM_CURATED_URL`, `USNM_REFERENCE_URL`, `USNM_COSMOS_ENDPOINT`, `USNM_QUICKWIT_*`, …); see `usnm-ingest --help` and [Development](development.md#ingest-pipeline). The release's layout settings for a full rebuild (`--partition-decade`, `--single-text-field`, `--page-language`) come from the deployment settings `USNM_PARTITION_DECADE`, `USNM_SINGLE_TEXT_FIELD` and `USNM_PAGE_LANGUAGE` ([operations](operations/rebuild-and-index-storage.md#full-rebuild)).
- **Deployment settings** (read by the Bicep parameters, `infra/main.bicepparam`, which set the variables above in each environment): the public choices are committed in `infra/env/<env>.json`. The private ones (addresses, principals, resource ids) are in the settings store, an App Configuration store shared by the subscription's environments, under the environment's label. The stack's outputs and identifiers stay in the local file (`~/.config/usnewsmap/<env>/.env` when that directory exists, otherwise `.azure/<env>/.env`). `infra/env/schema.json` says where each setting lives; [`infra/README.md`](../infra/README.md#settings-and-the-deployment-stack) and [operations](operations/environments-and-deploys.md#settings) say how to change one.
  - **Searcher rollback:** `USNM_SEARCHER_APP_RETAIN` (boolean, default `false`) retains the searcher app and its reader role while `USNM_SEARCHER_APP` is off and the API returns to its sidecar. It does not change API routing. Clear it only after the sidecar revision is ready and serving; see [the two-step rollback](operations/search-serving.md#searcher-app).

`USNM_API_MAX_REPLICAS` is an infrastructure setting (default `2`, a positive integer), used for both the API's scale maximum and the allocation of shared-searcher slots. It is not the observed number of running replicas. A standalone API process still reads `USNM_COMPUTE_CONCURRENCY` as its own slot limit.
